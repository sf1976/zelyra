# Zelyra 0.9.2 Release Plan: IDE Language Services

**Status:** in progress · experimental · no production approval. Independent human
product acceptance remains reserved for 1.0.0.

## Implemented and locally checked

- [x] F1 and the help control open bilingual help for core language terms at the
  cursor. File properties show path, type, save state, and format/check actions.
- [x] The action finder is available from the toolbar and Ctrl+Shift+P, filters
  available tasks, and supports keyboard navigation.
- [x] `zelyra --help` ends with German and English getting-started paths for
  both the invoice tutorial and a minimal project; key commands explain their
  purpose and database requirements. The usage and quickstart both show
  `zelyra editor` as a direct launch in the current folder, with an optional
  directory argument. Studio opens the default browser on a desktop; `--no-open`
  and a printed URL support headless environments. The database and web app are
  not started automatically.
- [x] Completion adds declarations from the linked project model to language
  keywords; Ctrl+Space opens the suggestion list. F12 goes from a function or
  type name to its definition in the active file or a directly imported module.
  Navigation is refused while a file is unsaved so stale source positions are
  not opened.
- [x] Zelyra files receive compiler diagnostics for the current, possibly
  unsaved source after a short pause. Checking uses a private temporary project
  copy, leaves project files untouched, and converts source positions for the
  browser editor.
- [x] Ctrl+Space completes parameters and local `let`, loop, and match bindings
  from the compiler AST inside syntactically valid functions. Bindings follow
  the active block; explicit types are shown. If the source is incomplete,
  project and keyword suggestions remain available while local suggestions wait
  for parseable source.
- [x] The action finder runs `main.zyl` only after an explicit selection. Studio
  shows the exit status and program output, stops execution after 15 seconds,
  and limits each output stream to 64 KiB. Values from recognized secret
  environment variables and the local `.env` file are replaced before display.
  The program runs with its configured Zelyra capabilities; Studio does not
  start it automatically. Interactive stdin is unavailable.
- [x] Rust verification of unsaved-source checking and a Chromium browser flow
  for F1, file properties, diagnostics before saving, and subsequent save.

The action finder currently covers common local IDE actions, not every project
task. Scope-aware semantic references, type inference, symbol/route properties,
and integrated verify/test tasks remain open.

This work adds read-only literal search across saved `.zyl` files; each result
opens its file, line, and column. The search asks users to save open changes
first and does not replace semantic reference analysis. Shift+F12 also finds
exact identifier tokens in saved `.zyl` files. It uses the Zelyra lexer, so
comments and strings are ignored. Results are lexical, not scope-aware: names
from another scope may also appear. The search is limited to 500 matches,
2,000 project files, 1 MiB per file, and 32 MiB of total source; exceeding a
limit or encountering unreadable source marks the result set incomplete.

The project map is derived from the compiler project model and shows modules,
imports, tables, views, CRUD resources, pages, APIs, and functions. It draws
only unambiguous relationships: module imports, declaration ownership,
CRUD-to-table links, page-to-view links, and uniquely resolved API handlers.
Selecting a node opens its source location. Ambiguous or bounded-out
relationships visibly mark the map incomplete. Input is limited to 2,000
project files, 1 MiB per `.zyl` file, 32 MiB total, 500 nodes, and 1,000 edges;
database queries and dynamic relationships are outside this compiler map.

## Goal

Studio should make as many everyday language and web-framework tasks as
possible understandable and directly operable. Properties panels, task selection,
and guided flows should reduce manual detail work and command memorization. The
compiler remains the source of truth for syntax, symbols, diagnostics, and project
relationships; every generated change remains ordinary, reviewable Zelyra source.

The invoice tutorial is an end-to-end guided start: `zelyra --tutorial invoice`
creates the app and theme, starts the local MariaDB/web Compose application,
and applies the schema. The Compose web service supplies database configuration,
so beginners do not export `DATABASE_URL` or run separate database and server
commands. Missing Docker produces a concrete diagnostic and one retry command.
`--no-start` creates the scaffold without Docker when only project files are
needed. The example also gets a responsive, professionally styled theme.

## Scope

- A context-sensitive help and properties sidebar shows file information and
  supported language terms in clear language. F1 and the help control open it;
  file properties provide direct format and check actions. Expanding this to
  symbols, routes, views, forms, and resources remains in scope. Supported edits
  can be checked in a source preview and explicitly applied.
- A task/command finder makes supported language and framework actions easy to
  discover. Help for the command at the cursor can be requested with F1 or a
  visible help control and shows its description, options, examples, and known
  limitations.
- Where the project model and compiler allow fast results, Studio updates
  hints while typing. Full compiler diagnostics can be requested without leaving
  the IDE for a shell. Diagnostics have correct file and source locations.
  Incomplete or unchecked states are visible; compiler errors are not hidden as
  warnings.
- Compiler-backed completion, symbol navigation, and find/references cover the
  documented language compatibility line 0.1.
- Local completion uses the current unsaved source and cursor position; it does
  not infer types. Type inference, overload resolution, and semantic reference
  analysis remain outside this step.
- Shift+F12 finds lexical occurrences of an identifier in the project and opens
  the file, line, and column. These results are not a complete semantic
  reference analysis.
- Format, check, run, and supported verification tasks can start in Studio.
  Progress, completion, output, and failures are visible; secrets are redacted.
  Redaction covers recognized process environment and `.env` values; it cannot
  generally identify secrets embedded directly in source code.
- Project, module, import, route, and resource relationship diagrams are
  deterministic views of the compiler project model. Selection navigates to
  source, object, and diagnostics. Unresolved edges are marked unknown.

The current IDE improvements give the help and properties tabs tab semantics
and keyboard navigation. The action finder exposes its active option through
`aria-activedescendant`. Project and database diagrams preserve their individual
named, keyboard-activatable nodes for screen readers by exposing the SVG as a
group; visible focus indicators show the current selection. Project folders
announce their expanded state, and search results are exposed as a region. A
final manual accessibility review remains a release criterion.

## Exit criteria

- [ ] Browser E2E covers property selection, requestable command help, live
  diagnostics, navigation targets, keyboard access, and resizing.
- [ ] Positive and negative multi-file projects cover completion, navigation,
  identifier occurrences, symbols, file switching, and diagnostic ranges.
- [ ] Formatting is repeatable and writes only after an explicit action.
  Compiler tasks show status and redacted output.
- [ ] Diagram data is deterministic across runs and includes source locations;
  unknown or dynamic relationships are not guessed. The current project map is
  a bounded compiler-backed subset.
- [ ] Keyboard operation, focus, screen-reader labels, and contrast are verified
  for new Studio controls.
- [ ] Workspace, editor bundle, installers, full E2E suite, MariaDB matrix,
  MySQL/PostgreSQL subsets, fuzzing, dependency audit, and Linux/Windows
  artifacts pass on the exact candidate.
- [ ] German and English references, roadmap, release notes, and handbook match
  shipped behavior and database limits.

## Boundaries

The graphical schema designer for adding/changing table fields and creating the
selected database from Studio are planned for 0.9.3. The 0.9.2 properties
sidebar and guided IDE workflows do not manage database schemas. Full
MySQL/PostgreSQL parity, arbitrary shell execution, cloud dependencies, and
external AI services are out of scope.

This release does not replace independent human product acceptance and is not
production approval.
