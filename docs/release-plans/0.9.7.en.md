# Zelyra 0.9.7 — Studio, invoice tutorial, and database hardening

**Status:** in development · **Language line:** 0.1 · **Release maturity:** experimental

## Goal

The multi-file invoice tutorial should look like a polished small business app
on desktop and guide beginners through customers, items, invoices, and reports.
The Studio project map must show module relationships correctly and explain why
any unresolved relationship remains open. Notification, migrator, and database
support continue to be hardened. No feature is declared production-ready;
human acceptance of the exact candidate remains reserved for 1.0.0.

## Scope

- [x] Show real metrics from stored tutorial records and guide the user from
  customer and item records through invoice entry and reporting. Preserve the
  print view with net, 19% VAT, and gross totals.
- [x] Responsive desktop, tablet, mobile, and print layouts for the dashboard
  and generated CRUD pages. The optional Tabler CSS integration is served
  locally from the pinned MIT package; no CDN, JavaScript framework, telemetry,
  or external account is required. Record the package version and license.
- [x] Resolve page and CRUD layouts within their own module or through
  explicitly imported public views. Include table views and provide stable
  diagnostic codes with localized explanations for ambiguous, unresolved, and
  limited relationships. Do not guess unknown SQL joins.
- [ ] Add personal read receipts and recipient authorization to notifications;
  keep retention, templates/attachments, and optional SMTP delivery bounded,
  tenant-scoped, and explicitly configured. This connected authorization and
  delivery work moves to the 0.9.8 plan so it can be closed with dedicated
  recipient and read-receipt checks rather than shipping a shared `read_at`
  field as if it were a personal state.
- [ ] Continue the versioned Laravel analysis and verify its mappings against
  tenants, permissions, relationships, transactions, files, payments, and
  public endpoints. This staged review, including generated-application flows,
  closes in 0.9.8; missing evidence remains visible and never implies parity.
- [ ] Continue MariaDB, MySQL, and PostgreSQL workflow coverage, foreign keys,
  and tenant-filtered CRUD. Document the exact server versions for each claimed
  backend feature.

## Evidence and exit criteria

- A project-map regression covers the imported tutorial layout and a table
  view; output is deterministic. Ambiguous and truncated cases have negative
  tests.
- Browser end-to-end loads the dashboard and CRUD paths with a prepared schema,
  computes metrics from stored records, and exercises the print/PDF path.
  Desktop and narrow viewports receive browser coverage.
- The stylesheet response serves Tabler locally and works without network
  access; the user-supplied CSS size limit stays separate from the built-in
  design library.
- Workspace tests, Clippy, formatting, Docker/database E2E for supported
  backends, Studio and tutorial E2E, and documentation checks pass on the exact
  release candidate.
- Security and database limits are documented in both languages; README,
  implemented inventory, website handbook, release notes, SBOM, verification
  record, and artifact hashes match the released tag.

Passing CI is not human product acceptance. The first productive release stays
reserved for 1.0.0 after review of its exact candidate.
