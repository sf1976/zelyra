# Zelyra 1.2.34 — Static Laravel migration guard handling

## User outcome

The Laravel website importer can combine a narrow class of ordered schema
migrations without inventing columns from a callback Laravel would skip.

## Scope

- Recognize a `Schema::table` callback only when its complete supported body is
  one `if (!Schema::hasColumn(table, column))` guard.
- Skip that callback only if a prior migration in deterministic source order
  statically declares the guarded column.
- Continue to reject mixed callbacks and unsupported/dynamic migration logic.
- Do not execute PHP, read `.env`, query application rows, or modify the source
  project.

## Acceptance evidence

- Unit tests cover skip, apply-if-absent, and mixed-callback rejection.
- A fresh static analysis of `/opt/siedelmann-laravel/app` must stop rejecting
  the `quotes` merge and preserve only columns present after ordered Laravel
  migration execution.
- The source-only scaffold/compiler/inventory integration check must pass.
- Run formatting, workspace check/test/Clippy, handbook validation, and
  `git diff --check` before proposing the change.

## Explicit limitation

This is schema-analysis hardening, not a complete Laravel import. The current
acceptance project remains at 2,268 analyzer findings; controller workflows,
routing, and most Blade behavior remain unmigrated.
