# Zelyra 1.0.7 – Language, runtime, and documentation work log

## Objective

Turn limitations reported across 20 practical programs into verifiable,
versioned language and runtime features, then publish `v1.0.7` after all release
checks pass.

## Acceptance criteria

- If expressions, record updates, and typed lambdas with `map`, `filter`,
  `find`, and `reduce` parse, type-check, and execute.
- Recursion depth is configurable through `[runtime] max_stack_depth`; deep
  calls still fail with a precise diagnostic instead of overflowing the stack.
- Match guards and nested record patterns are checked and executed; guarded
  arms do not count as exhaustiveness proofs.
- Contextual field names such as `version`, `type`, and `status` work in record
  declarations, constructors, and field access.
- Tuples work as function return values and for destructuring assignments
  outside loops.
- Server-side PDF rendering has a documented, tested Zelyra API; PDF
  attachments can be delivered safely through the existing mail outbox.
- German and English references, examples, configuration docs, roadmaps, and
  release notes describe only behavior that is implemented and tested.
- Full Rust, browser, tutorial, Docker, package, and release gates pass before
  tagging and publication.
- Identity types, API error contracts, runtime limits, auth routes, slot
  fallbacks, and `parallel` synchronization are checked against existing
  Zelyra semantics and documented in both handbooks.

## Milestones

1. Inventory and syntax/type-system tests.
2. Expression syntax, higher-order functions, and record updates.
3. Match destructuring, guards, contextual names, and tuple assignment.
4. Configurable recursion depth with safety limits.
5. Server-side PDF, mail attachments, and outbox integration.
6. Bilingual docs, examples, roadmaps, version/release metadata.
7. CI, review, merge, tag, and published artifact verification.

## Additional implementation requirements

| Topic | Actual Zelyra semantics | Status |
| --- | --- | --- |
| Nominal IDs | `type OrderId = Id` rejects an `Int` literal; `type OrderNumber = Int` remains a transparent domain alias. | tested |
| API errors | An error payload in `errors { ...: Payload }` requires `output Result<T, E>`; the `Err` type must match the payload. | present, tested |
| Step budget | `zelyra run file.zyl --max-steps N` counts statements and expression evaluations in one shared budget, including `parallel` branches. A parallel overrun points deterministically at the `parallel` statement. | tested |
| Database transactions | `zelyra check` validates the block offline; execution without a database runtime returns `E-RUNTIME-001`. | present, tested |
| Auth routes | `/login`, `/logout`, `/account/sessions`, optional reset/MFA routes, and a configured admin path have method, CSRF, and permission checks. Optional tables and options govern availability. | present; no fixed URL count |
| View slots | Supplied slots replace fallbacks; omitted named slots render their fallback content. | present, CLI tests |
| `parallel` | Only `await` bindings are accepted; the block waits for all started tasks and exposes their typed values in the outer scope. | present, runtime test |
| PDF mail | `render_pdf("ViewName", record)` returns `Bytes`; `mail_queue` can store one PDF attachment in the outbox. | locally tested; CSS/graphics rendering and live mail remain unverified |

## Limits and risks

These reports identify language and ergonomics gaps, not demonstrated security
vulnerabilities or CVEs. Recursion must remain bounded to protect the stack and
memory. PDF rendering must stay local and reproducible; browser/system
dependencies, HTML security, and mail attachments must not introduce implicit
network access or telemetry.
