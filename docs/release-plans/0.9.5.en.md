# Zelyra 0.9.5 release plan: first-party mail and SMTP

**Status:** in development; experimental until all gates pass. This milestone
establishes local-first text/HTML mail delivery without requiring a cloud mail
provider. Named templates and file attachments are deliberately deferred until
their safe project-resource and size-limit contracts are implemented.

## Scope

- Provide an explicit Zelyra mail API for text and HTML alternatives, safely
  encoded headers, bounded messages, and compiler-checked capabilities.
- Support SMTP authentication, implicit TLS, and STARTTLS with certificate
  verification; allow a bounded, explicitly configured private root CA.
  Never downgrade or send credentials over a plaintext connection.
- Bound SMTP connection timeouts. Integrate retryable delivery with the
  MariaDB transactional outbox while documenting at-least-once delivery and
  the duplicate window. State the MariaDB/MySQL boundary clearly; PostgreSQL
  mail outbox support remains separate work.
- Include local configuration guidance and a local SMTP sink for development
  and automated tests. Do not require an external account or service.

## Exit criteria

- [ ] Positive and negative integration tests cover local SMTP success, MIME
  text/HTML alternatives, SMTP authentication, trusted and untrusted TLS roots,
  the transport timeout, configuration rejection, secret redaction, capability
  checks, retries, and transactional queueing.
- [ ] Tests prove SMTP host allowlisting, TLS mode selection, plaintext loopback
  restrictions, safe header handling, and the message size limit. TLS
  certificate rejection and relay timeout remain explicit release gates.
- [ ] Configuration, environment variables, security classification, defaults,
  and command effects are documented in English and German.
- [ ] Generated projects explain how to develop and test mail against a local
  sink without publishing credentials or sending messages to real recipients.
- [ ] Release CI, dependency review, release artifacts, checksums, SBOMs, and
  handbook validation pass for the exact candidate.

No release claim may imply exactly-once delivery, universal SMTP relay
compatibility, or production approval. Security review and the 1.0.0 human
acceptance gate remain required.
