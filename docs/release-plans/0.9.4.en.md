# Zelyra 0.9.4 Release Plan: CLI and Tutorial Reliability

**Status:** Implementation complete; release workflow pending. Zelyra 0.9.x remains experimental; human acceptance and
production approval are reserved for 1.0.0.

## Goal

Make the documented CLI dependable for project setup and database work, and
verify that the invoice tutorial can create and display a customer from Studio's
local web preview.

## Scope

- Audit documented top-level and nested commands, detailed help in German and
  English, supported options, expected error behavior, and runnable examples.
- Explain `zelyra db create` accurately: it emits checked SQL and does not
  connect to or create a database. Explain when to use `db setup` and
  `zelyra setup <directory> --all`.
- Stream Docker Compose build/start output, show schema setup progress and
  useful final errors, and print the application URL.
- Ensure the invoice tutorial writes its protected `.env` even with
  `--no-start`; keep credentials out of terminal output.
- Treat MariaDB's unqualified `DECIMAL` as its documented `DECIMAL(10,0)`
  storage default so rechecking an unchanged schema does not propose a
  destructive type change.
- Exercise Studio preview against MariaDB: load the customer form, submit a
  customer, follow the redirect, and find the new record in the list. If a CRUD
  query fails, give a safe database/schema hint without exposing SQL errors or
  connection secrets.
- Preserve the staged 0.9.5–0.9.8 roadmap for language type coverage, the
  Laravel migration graph, relational/chart IDE work, and presentations.

## Acceptance Gates

- [x] Every documented nested help path succeeds in English and German and
  returns command-specific help.
- [x] Offline command examples, setup error cases, and the `db create` output
  semantics have regression coverage.
- [x] `zelyra setup <directory> --all` completes against an isolated local
  MariaDB Compose project and visibly reports progress and the URL.
- [x] The invoice Studio-compatible customer create/list flow passes against
  MariaDB; tutorial CSS is served, `.env` remains private, and repeated schema
  setup is a no-op.
- [x] `cargo fmt --all -- --check`, `cargo test --locked --workspace`, Clippy,
  documentation checks, release metadata checks, and the applicable Docker
  checks pass on the release commit.
- [ ] Release assets, checksums, SBOM, and provenance pass the established
  release workflow. No independent human acceptance is claimed; it remains a
  required 1.0.0 gate.
