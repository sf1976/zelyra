# Delivery status: Zelyra 1.1.5 through 1.3.0

Status: active module/package, Laravel website import, and interpreter roadmap.
Zelyra v1.2.28 is the current published stable release. The v1.1.5 and v1.2.0
module and operations foundations have shipped across later releases but their
broader package, integration, and deployment evidence remains open. The owner
reprioritized a new Laravel-built website importer on 2026-10-20. Version 1.3.0
is not complete. This file records current scope and remaining evidence.

## Removed from the project

At the owner's request, the experimental Laravel migrator was removed from the
active repository in v1.1.2. Its source, guides, tests, and reports are
preserved in a local archive. On 2026-10-20 the owner reprioritized importing
websites built with Laravel for migration testing in Zelyra. The new importer
is planned for v1.2.27–v1.2.30 and must produce native reusable Zelyra modules;
it will not restore the old tool unchanged or reproduce Laravel's runtime.

### Checked token-form foundation — 2026-10-20

Standalone forms now support `verify sql<T> { SELECT ... }` for a read-only GET
gate and `require_match` for direct SQL action blocks. Form route captures are
type-checked as strings in both queries. GET returns 404 for a missing token

`post_only` form may share a path with a GET page, but cannot also declare
`verify`; GET validation then belongs to that page.

`examples/csv_mailer_unsubscribe.zyl` is a checked native Zelyra example. The
new `tests/mariadb-form-route-e2e.sh` was run against a temporary MariaDB 11.8

### Concurrent upload request-budget correction — 2026-10-20

The PR's rolling GitHub toolchain had advanced to Rust 1.99.1, where Clippy
rejects the deprecated `AtomicUsize::fetch_update` API. Reservation now uses a
bounded `compare_exchange_weak` loop and remains compatible with Rust 1.98.
A concurrency regression test exposed that `bool::then_some` eagerly created
the RAII budget guard even when reservation failed. Its destructor then
subtracted bytes that had never been reserved, which could admit more aggregate
request bodies than the configured limit. Guard construction is now
conditional; 32 concurrent reservations against an eight-byte budget admit
exactly eight and release the full budget. Focused web tests and workspace
Clippy pass locally; PR CI must be rerun after this fix.

## 1.3.0 — AST reference, MIR, and bytecode

- AST remains the reference backend and default. MIR and versioned bytecode are
  opt-in experimental subsets with verification, step/stack limits, HostServices,
  and differential tests.
- Supported slices include typed control flow, records, collections, tuples,
  enums/match, closures, and selected host/SQL/outbox operations. Unsupported
  operations must fail closed.
- Goal: make verified Bytecode the default for `run`, `serve`, and tasks only
  after full supported-language, effect, capability, contract, resource, host,
  and diagnostic parity is proven. AST remains the reference and differential
  backend. Until those gates pass, AST remains the default and unsupported
  Bytecode operations fail closed. This is a portable Bytecode goal, not native
  machine-code generation.
- Open: full parity; broader differential, fuzz, and security coverage;
  reproducible performance measurements; and the backend-default release gate.

### Generated scalar differential corpus — 2026-10-20

The Bytecode test suite now generates 96 bounded integer expressions from a
fixed seed. Each case is evaluated independently in Rust and compared with the
AST interpreter, MIR interpreter, Bytecode VM, and a decoded encode/decode
artifact. The generated arithmetic remains far inside `Int` bounds, so this
test checks successful scalar results rather than overflow/error parity. The
focused test `cargo test -p zelyra-mir
generated_bounded_integer_expressions_match_independent_oracle_and_backends
--locked` passed. This adds evidence for the supported arithmetic slice only;
it does not establish full language or runtime parity.

### Checked integer operator error parity — 2026-10-20

Regression coverage now compares division and remainder failures across AST,
MIR, and decoded Bytecode. Division/remainder by zero and signed `Int` minimum
divided/remaindered by `-1` must return the same diagnostic message and exact
source span. `cargo test -p zelyra-mir
integer_division_and_remainder_failures_match_ast_mir_and_bytecode_spans
--locked` passed. This verifies four checked integer failure cases only; it
does not establish general error or step-accounting parity.

The differential case now also covers checked addition, subtraction, and
multiplication overflow plus negating `Int::MIN`. All eight checked arithmetic
failures retain the AST diagnostic message and exact span in MIR and decoded
Bytecode. The focused test is now
`cargo test -p zelyra-mir checked_integer_arithmetic_failures_match_ast_mir_and_bytecode_spans
--locked`; it passed. Other numeric types and runtime diagnostics remain open.

### Configured recursion-depth parity — 2026-10-20

A differential regression test now runs the same recursive function through
the AST interpreter, MIR interpreter, and decoded Bytecode. All three permit a
depth of 24 with a configured limit of 40 and reject it with a limit of 20.
The MIR call-frame limit now reports the source span of the call expression,
matching AST and Bytecode, instead of the callee declaration. The focused test
`cargo test -p zelyra-mir configured_recursion_depth_matches_ast_mir_and_bytecode
--locked` passed. This verifies one recursion-depth boundary and error span;
it does not establish full stack-resource parity or make Bytecode the default.

### Zero-step source-location parity — 2026-10-20

A zero-budget differential case now confirms that AST and MIR report the
same first-statement span, while decoded Bytecode reports the same source line.
The MIR interpreter charges an instruction using its own source span instead
of the enclosing basic-block span. The test exposed a remaining Bytecode
precision gap: its budget error points to the first emitted expression
operation, not the AST statement start. Exact Bytecode byte-range/column parity
and broad step-accounting parity remain open. The focused test
`cargo test -p zelyra-mir zero_step_budget_failure_keeps_source_location_across_backends
--locked` passed.

## 1.2.0, 1.2.5, and 1.2.8 — operations through integration

The authoritative release allocation for commands, schedules/jobs, typed
request/forms, scoped query foundations, the `public/` directory, Apache/Nginx
proxy deployment, and fixed-port OS services is in
[`ROADMAP.md`](../ROADMAP.md). In particular, service installation must fail
when the requested port is occupied; changing a port is explicit and must
restore the previous service configuration if restart fails.

### Linux systemd service slice — implemented on the current work branch, unreleased

- `zelyra service install --port <port>` writes a per-project systemd user unit
  for the canonical current directory. It references an existing project
  `.env` without copying values, uses an explicit loopback port, checks the
  project first, and rolls back the unit if systemd start/readiness fails.
- `change --port`, `status`, `restart`, and `remove` are implemented. Port
  change stops the old process, rejects an occupied target, atomically replaces
  the unit, reloads systemd, and verifies the listener. Failed startup restores
  the prior unit and attempts to restart the prior service. Manually edited
  units are not overwritten by port changes.
- Ports are never automatically selected. Service state is managed with
  `systemctl --user`; enabling user lingering for startup before login remains
  a deliberate administrator action. Apache/Nginx can proxy to the loopback
  listener but do not execute Zelyra code.
- Focused tests cover argument validation, port conflicts, path escaping and
  newline rejection, generated-unit verification with `systemd-analyze`, and
  simulated occupied-port and failed-restart rollback paths. An additional
  live test against systemd 257 in a private D-Bus session covered install,
  restart, rejection of an occupied target port with restoration of the old
  listener, port change, and removal. The minimal application returned HTTP
  200 before and after the port change; both ports were closed after removal.
  Reboot-before-login behavior with systemd lingering remains untested.
- Tenant-query HIR, the full typed request/form lifecycle, safe retention of
  allowed old input, and persistent transactional jobs moved out of the bounded
  1.2.5 release scope and into 1.2.6. The resident scheduler runs inside the
  active `serve` service; distributed scheduler leases and persistent retries
  also remain open.
- Audit of the five reported compiler gaps against code and workspace tests:
  payload enums, typed string interpolation, generic structs/records, and
  opt-in mutable arrays are already implemented; the full workspace test run
  confirms their existing positive and negative checks. The Bytecode VM remains
  a tested, limited subset, and changing its default remains open until parity
  is demonstrated. The roadmap now reflects this evidence.
- Schedule automation acceptance added: checked schedule declarations must
  drive idempotent outbox setup and the resident scheduler. The scheduler in
  `serve` reloads project source at each minute boundary and runs only current,
  valid declarations. Setup does not install cron rows and removes old
  Zelyra-managed `.zelyra/schedules.cron` files; foreign crontabs are never
  modified.
- CLI help and tutorial docs now state that manually started `serve` does not
  run schedules, cron export is only a preview, and the legacy trigger does not
  execute jobs. The resident scheduler runs only inside the installed, active
  Linux systemd service.
- Scheduler handlers now also have a configurable wall-clock limit:
  `[runtime].scheduler_job_timeout_seconds` applies to the resident service,
  defaults to 300 seconds, and accepts 1 through 86,400. On expiry the scheduler
  terminates the child process and logs the failure; Studio displays the
  effective value in its runtime budget dialog. A real child-process test
  verifies termination, while parser checks cover bounds and duplicate values.
  This is still not a durable job system: failed jobs are not retried
  automatically, and external effects that occurred before timeout cannot be
  rolled back.
- `zelyra schedule status main.zyl [--json]` reports declared schedules,
  service installation/activity, and the resulting scheduler state. It checks
