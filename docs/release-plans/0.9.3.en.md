# Zelyra 0.9.3 Release Plan: Database Workbench and Type Coverage

**Status:** Published as stable, still experimental release `v0.9.3` on
2026-10-11. The immutable tag points to
`2265fbddb4d7557219b1e19d79171c74d02c7d04`; main CI and release packaging passed.
This is not production approval or a human acceptance result. Independent product
and accessibility acceptance remains scheduled for 1.0.0. See the
[0.9.3 candidate verification](../release-readiness/0.9.3-candidate-verification.md)
for exact checks and artifact hashes.

## Goal

0.9.3 connects gaps found in the invoice and type exercises with a safer Studio
database workbench and the first read-only Laravel migration report. Visual and
generated changes remain ordinary source code; database migrations are never
applied silently.

## Included work areas

- CSV round trips with UTF-8, semicolons, quotes, newlines, field validation,
  error report, sorting, and exact decimal arithmetic. The example is runnable
  and covered by a CLI integration test.
- Labyrinth grids with validation, breadth-first search, shortest paths,
  counters, rendering, file round trip, and reachable/unreachable cases.
- Native Zelyra values for Decimal, Date, Time, Duration, and Bytes, plus the
  List alias, heterogeneous Tuple, and deterministic Set values. Type coverage
  explicitly distinguishes supported, partial, and missing concepts; enums,
  user-defined generics, function values, and identity-bearing objects remain
  open through the 0.9.9 feature-freeze review.
- Tutorial and Studio startup workflows with a local browser address, project
  theme CSS, separate web-preview lifecycle, console execution without
  interactive input, and detailed CLI help including `zelyra routes`.
- Studio data browser: explicit loading, at most 25 rows per page, read-only,
  session-protected, safe identifiers, and text rendering. Source columns can
  be added and simple fields edited. Preview, compiler diagnostics, hash
  check, and confirmation are required. The database is not changed. Studio
  can create a declared MariaDB database after explicit confirmation when its
  connection is already configured; schema application remains separate and
  reviewed.
- Initial Laravel inventory: Markdown/JSON, source locations, status, and next
  steps. It does not read `.env` files, run PHP or Artisan, connect to a
  database, or write inside the source project.

## Remaining technical limits

- The Laravel Migrator is a pattern scanner, not a PHP parser or complete
  route-to-data project graph. Optional scaffolding and the Laravel/package
  compatibility matrix follow in later releases.
- Studio does not yet provide backend/connection selection or a complete
  risk/plan view. Database creation is limited to MariaDB with an existing
  connection. MySQL schema introspection is not supported;
  MySQL runtime support is limited to typed parameterized queries. Database
  parity must be proven for each release and exact server matrix.
- Type coverage is not complete. `examples/type_system/README.md` lists the
  remaining language concepts; no open item may be presented as supported
  before 0.9.9. Rerun the final type coverage program after these language
  changes are complete.
