# Zelyra 1.2.26 — interactive language console

## Goal

Provide `zelyra console [entry.zyl]` as an incremental, compiler-checked
interactive Zelyra environment built on the AST reference runtime.

## Required behavior

- Keep values and declared variables across input lines without replaying prior
  statements or repeating side effects.
- Accept piped input as well as a terminal. Add a persistent history file only
  for interactive terminals; do not make shell-history failures fatal.
- Continue after parse, type, runtime, contract, and step-budget errors.
- Support multi-line blocks with an explicit continuation prompt and recover
  cleanly on Ctrl+C / EOF.
- Add the documented meta commands: `:help`, `:tables`, `:schema`, `:tenant`,
  `:commit`, `:rollback`, `:clear`, `:quit`, and `:exit`.
- Preserve project functions, records, enums, imports, capabilities,
  contracts, configured stack depth, and step budgets.
- Support `--backend ast|bytecode`; reject a backend/input combination that
  does not have equivalent checked runtime behavior.
- Resolve the project database from its declared connection and protected
  environment. Do not expose credentials in prompts, history, diagnostics, or
  process arguments.

## Transaction sandbox

`--sandbox` is the default; it must own a real database transaction for the
entire session. SQL statements must execute on that pinned transaction, and
`:commit` commits the current batch and starts a fresh sandbox transaction;
`:rollback` rolls it back and starts a fresh sandbox transaction. Leaving the
session rolls back the active batch. `--persist` is an explicit opt-in to
ordinary committed database behavior. Never simulate rollback by running SQL
through auto-committed pool calls.

If the runtime cannot preserve a pinned transaction and typed interpreter
bindings together, keep database statements disabled in the REPL until both
can be guaranteed; the acceptance test must not claim rollback coverage.

## Verification gates

- Piped-state test: `x = 10`, `y = 20`, `x + y` prints `30`.
- Recoverable runtime failure test: division by zero does not prevent the next
  expression from evaluating.
- Multi-line parsing, Unicode, EOF, Ctrl+C, and history tests.
- Compiler diagnostics and capabilities remain enforced for every submitted
  unit; no unchecked textual interpolation into project source.
- MariaDB sandbox integration proves an inserted row disappears after normal
  exit and after an explicit `:rollback`; `:commit` persists the first batch
  while later uncommitted work is rolled back.
- `tests/language-console-mariadb-e2e.sh` automates the transaction lifecycle,
  including `--persist`, using an isolated disposable MariaDB container.
- Run workspace test/check/Clippy, formatter, release metadata, and artifact
  smoke gates.
