# Zelyra 1.2.35 — Laravel unsigned integer storage widths

## Goal

Preserve the physical MariaDB storage widths of Laravel unsigned integer
columns in generated Zelyra schemas, without changing their Zelyra value or
identity types.

## Scope

- Add the checked `unsigned_storage` column modifier for `UInt`, `Id`, and
  table-relation columns.
- Preserve `id()`, `foreignId()`, and the five Laravel unsigned integer
  migration methods from `unsignedTinyInteger()` through
  `unsignedBigInteger()` in importer output and machine-readable reports.
- Emit the matching MariaDB `UNSIGNED` type and compare it against live schema
  metadata, ignoring only legacy integer display widths.
- Use `NUMERIC(20,0)` for ordinary `UInt` fields on PostgreSQL and SQLite,
  which do not provide the same native unsigned integer type family. Keep
  auto-incrementing IDs and relation columns on the backend's matching native
  key types so generated keys and foreign keys remain compatible.

## Boundaries

This does not preserve signed Laravel integer widths, prove every source
database constraint, or claim full Laravel schema parity. `UInt` retains its
Zelyra semantics; a narrower physical column can reject values that the
language type itself permits. PostgreSQL and SQLite do not receive MariaDB's
per-width unsigned range constraints; their auto-incrementing IDs and relation
columns retain native signed key types.

## Verification

Positive and negative parser/database tests cover the modifier and DDL.
Importer tests cover each Laravel unsigned width, IDs, foreign IDs, generated
source, JSON metadata, and MariaDB live-schema type normalization.
