# Zelyra 0.9.9 final technical release plan

**Status:** planned; final implementation and feature-freeze milestone before
independent human acceptance. Zelyra 0.9.9 is not a production release.

## Mandatory carry-over from 0.9.8

- [ ] Close or demonstrably resolve every open item in the
  [0.9.8 release plan](0.9.8.en.md). In particular, run clean install,
  upgrade, rollback, migration, backup, and restore rehearsals on the exact
  promised operating systems and database versions; review and disposition
  security, license, privacy, resource, and secret-redaction findings; and
  verify reproducible offline artifacts, SBOMs, and provenance.
- [x] Repeated the 80-case language corpus and independent numeric comparisons
  on the 0.9.9 source build (`6bc6cf28a6e420411df210dcfd79add96fb26d2cf6eed531bb4d5d253698d3d9`).
  All 20 tasks and 35 controlled negative cases pass; 100/100 repeated task
  runs and 400 independent numeric comparisons pass, with zero unexpected
  outcomes across 80 cases. Four documented observations remain: deep
  recursion now returns a source-located runtime error, ordinary CLI execution
  remains unlimited unless `--max-steps` is set, Decimal arithmetic retains
  its documented nine-digit scale, and a 5,000-term expression evaluates
  normally. See [the 0.9.9 language review](../release-readiness/0.9.9-language-review.en.md).
- [x] Generic functions are implemented on the development branch: inferred
  and explicit type arguments, nested calls, arrays, `Option`, `Result`,
  imported modules, stable generic diagnostics, and positive/negative
  compiler/runtime tests are covered by the type-system example and regression
  tests. User-defined generic records and enums are also implemented. General
  constraints/traits and generic aliases remain documented omissions; the
  complete language gate still requires an explicit scope review.
- [x] Payload-carrying enums are implemented on the development branch:
  checked constructors and pattern bindings, exhaustive matches, controlled
  diagnostics, JSON round trips, and public enums across module imports have
  positive and negative regression coverage.
- [x] Named function values and typed indirect calls are implemented:
  `&name` and `&module::name` store references to named, non-generic functions.
  Signatures and capabilities are checked and propagated indirectly; runtime,
  module, JSON, and SQL boundaries are covered. Closures, capturing local
  functions, and generic function references remain explicitly outside this
  bounded slice.
- [x] Generic user-defined records and enums are implemented: explicit and
  field/payload-inferred type arguments, nominal runtime values, concrete
  payload checking in `match`, typed JSON round trips, module imports, and
  positive/negative compiler/runtime regressions. Persistent SQL columns reject
  generic records explicitly. General constraints/traits, generic aliases, and
  generic function references remain outside this scope and are recorded in the
  specification and type matrix. The tagged `Result` JSON codec remains
  unchanged.
- [x] `format_text(value)` explicitly formats supported scalar values for
  display without JSON quoting or implicit coercion. Collections, records,
  variants, `Result`, and functions fail with a stable type diagnostic.
- [ ] Recheck every prior language, CLI, and runtime failure report, including
  setup/database/editor/tutorial paths. Errors must be reproducible and
  understandable; existing successful programs must keep their results. Add
  regression coverage for each newly found issue before completion.
- [x] Add an opt-in CLI color palette (`ZELYRA_COLOR=auto|always|never`) with
  `NO_COLOR` and `CLICOLOR_FORCE` handling, plus a brief Studio splash that
  respects saved theme, locale, and reduced-motion preference. Terminal and
  bundled-asset checks pass; the complete browser suite remains a release gate.
- [ ] Provide complete evidence for the Laravel Migrator, business-relation and
  tenant security checks, notification workflow, and integrated Studio/invoice
  tutorial/SMTP flow carried over from 0.9.8. Unsupported mappings must never
  be generated silently.

## Exit criteria

- [ ] Complete and verify the IDE workspace and compiler-backed language
  services planned for 0.9.1–0.9.2, including multi-file diagnostics,
  navigation, completion, formatting, and task execution. Light and dark
  appearances must cover every Studio surface, persist the selection, and work
  with keyboard navigation and checked contrast.
- [ ] Complete and verify the database workbench and relational CRUD design
  planned for 0.9.3–0.9.4, including explicit previews, compiler checks, and
  safe apply boundaries. Edit table fields and foreign keys through property
  pages and a clear relation view; show the resulting plan before applying any
  change.
- [ ] Configure business charts from tables and saved views through a Studio
  assistant: choose a data source, grouping, measure, time range, and filters;
  inspect a preview; and save a validated project file. Common charts must not
  require users to know JavaScript libraries or their option objects.
- [ ] Assemble simple business presentations in Studio from saved charts,
  metrics, table views, and authored text; review them in a slide preview and
  export them as PDF. Save presentations as inspectable project files without
  requiring external cloud services or user-written JavaScript.
- [ ] Pass every mail and SMTP requirement in the separate 0.9.5 release plan,
  including local sink coverage and verified TLS behavior.
- [ ] Complete and verify tenant-scoped notification storage from 0.9.6 plus
  recipient-level access controls, preferences, retention, and optional SMTP
  delivery from 0.9.7.
- [ ] Close the 0.9.7 MariaDB, MySQL Server, PostgreSQL, authorization, MFA,
  and independent security review requirements for the published 1.0 support
  matrix. Record exact server versions and each remaining limitation.
- [ ] Pass the clean-install, upgrade/rollback, backup/restore, resource,
  dependency, documentation, SBOM, provenance, and offline rehearsals in the
  separate 0.9.8 release plan.
- [ ] Freeze language, CLI, project, runtime, database, IDE, tutorial, mail, and
  notification contracts. Permit only documented defect and security fixes
  after the freeze, with regression tests and compatibility review.
- [x] The language line uses value-semantic records and explicit database IDs.
  Classes with observable object identity, reference mutation, and inheritance
  are deliberately not promised for 1.0.0; the type inventory and handbook
  state this boundary explicitly. Records, generic records, enums, explicit
  field updates, ordinary functions, and typed named function values cover the
  domain-data and behavior cases in this language line without introducing
  shared mutable aliases. Function values remain partial because closures and
  generic function references are not implemented.
- [ ] Complete all technical CI and release gates on an immutable `v0.9.9`
  candidate; prepare bilingual human-study materials for the later exact
  `v1.0.0-rc.1`. Conduct no human acceptance on 0.9.9.
- [x] Keep independent human acceptance explicitly reserved for the immutable
  1.0.0 candidate. It is expected to be the only remaining gate after all
  technical criteria above pass.
Only after all technical criteria pass may the project state that human
acceptance is the sole remaining gate. If any implementation, security,
database, migration, packaging, or documentation blocker remains, 0.9.9 is not
complete. It must never be described as human-accepted or production-approved.

SQL Server, universal SQL portability, complete PostgreSQL parity outside the
published workflow matrix, mandatory cloud services, telemetry, and external
AI providers are not implied by this plan.
