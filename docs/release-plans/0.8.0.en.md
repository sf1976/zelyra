# Zelyra 0.8.0 release plan: visual schema map and guided CRUD

**Status:** in development. This release extends the local studio with safe,
compiler-checked database design workflows. It is not a production release.

## User outcome

A developer can open a configured project database, understand tables and
relationships, select a table, preview a generated CRUD module, and apply that
source change after Zelyra accepts it. Database data remains read-only in this
release.

## Scope

- Show a read-only, clickable relationship map with tables and foreign-key
  arrows. The detail view shows columns, keys, and differences between declared
  and live schemas. Make the source module for each declaration visible when
  that information is known.
- Let the user choose a table and fields, preview the generated Zelyra source,
  run compiler validation, inspect the source diff, and explicitly apply it.
- Keep schema writes and row mutations out of the visual workflow. Do not
  generate silently or overwrite files changed since the preview.
- Include the bounded local MariaDB transactional outbox already developed on
  the stacked 0.8 branch: an explicit typed enqueue in a business transaction,
  explicit one-event worker calls, bounded retry, and operator inspection and
  recovery. Delivery is at least once; handlers must be idempotent. This is not
  a general queue platform.
- Expand the 0.1 conformance corpus across lexer, parser, type checking, and
  formatting. Require accepted and rejected fixtures and formatter
  idempotence.
- Review and include the bilingual design for readable regex text editing.
  An executable CLI command is not a 0.8 promise; implementation is planned
  for 0.9.0.
- Keep the workflow local, avoid external code services, and document each
  database introspection path separately.

## Release gates

- [x] Test schema drift with source-only, live-only, nullable, and related
  columns. Source and live values remain separately visible; unknown database
  types retain their raw type instead of being silently reinterpreted.
- [x] Prove generated source passes the same compiler checks as hand-written
  code. The local compiler fixture also verifies that preview leaves source
  files unchanged.
- [x] Reject stale source versions before preview and before writing.
- [x] Test successful and failed connection paths and read-only introspection
  for MariaDB and PostgreSQL in CI. Schema display does not mutate schema or rows.
- [x] Prove outbox/business-row commit and rollback atomicity, lease safety under
  competing workers, bounded retry, crash recovery, payload limits, and
  redacted operator output on supported MariaDB versions. The integration test
  checks commit/rollback, concurrent claims, expired and stale leases, recovery,
  exhaustion, and acknowledgement.
- [x] Run the current accepted, rejected, and runtime fixture corpus on the
  development revision. Lexer/string, pattern-matching, and Option typing cases
  were added. Rerun it on the exact release candidate.
- [x] Update the bilingual editor guide, database compatibility matrix, and
  handbook examples.

Run automated release gates again on the versioned PR revision and final release
commit. Record artifacts and checksums in the
[release verification record](../release-readiness/0.8.0-candidate-verification.md).

Do not claim a complete IDE, unrestricted database designer, database parity
beyond the tested matrix, exactly-once delivery, or distributed queue support.
