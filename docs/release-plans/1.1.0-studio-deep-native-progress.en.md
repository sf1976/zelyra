# Zelyra 1.1.0 – Studio Deep-Native work log

## Objective and release boundary

Studio and `zelyra lsp` must use the same compiler-based language service.
Eight Studio tools, a secure event channel, recoverable multi-file changes, and
the existing single-binary distribution are acceptance requirements.
`v1.1.0-rc.1` is to be prepared. The request requires express authorization
before pushing a tag or publishing a GitHub release page.

Follow-up request on 15 October 2026: finish the Studio work first, then
verify five cited compiler gaps against code and close the actual gaps for
1.1.0. The user explicitly authorized publishing stable 1.1.0 after
successful acceptance. This supersedes the earlier no-publication boundary
for 1.1.0; release gates and verified artifacts remain mandatory.

Initial code inventory of the five items: user-defined payload enums with
exhaustiveness and generic structs are already implemented with positive and
negative tests (`runtime/src/tests.rs` around lines 511 and 969–1076). They
need regression review, not duplicate implementations. General string
interpolation, opt-in in-place array mutation, and a bytecode/AOT backend
appear absent in the initial search; define precise semantics and limits after
finishing the Studio modules. Claims such as “SQL injection is impossible” or
“99% of backends are complete” are not acceptance evidence and will not be
repeated as product guarantees.

Base: `origin/main` at `eaa57c3`, after `v1.0.7`; working branch
`feature/1.1.0-studio-deep-native`. The working tree had no user changes at
the start. This file records work and evidence; a checked box proves only the
specific scope stated beside it.

## Architecture and security decisions

### Multiple unsaved Studio files

- Studio now submits up to 16 open `.zyl` buffers with at most 1 MiB of source
  to the same project analysis service as LSP. Live diagnostics, verifier,
  typed holes, semantic navigation, project map, capability matrix, runtime
  profile, and canvas see the same import graph.
- The server validates every overlay path within the workspace, rejects
  symlinks, duplicate paths, and missing files, and never writes the buffers.
  Free-text search and actual program runs still use saved files; the UI keeps
  these actions separate.
- Targeted Rust tests for unsaved imports, source positions, syntax errors,
  duplicate paths, and unsafe paths passed. The browser test checked the
  shifted F12 source position in Chromium, Firefox, and WebKit. Chromium
  passed again after the last small frontend correction.
- `cargo test --workspace --locked`, `cargo check --workspace --locked`,
  `cargo clippy --workspace --locked -- -D warnings`, formatting, and UI
  metadata checks passed. Two external fixture tests remained `ignored`.
  The embedded JS bundle measures 551,600 bytes;
  the 400 KiB target remains open.

### Semantic F2 function rename

- The shared `semantic_index` now creates compiler-checked rename plans for
  both LSP and Studio. Scope, resolved references, source positions, name
  conflicts, and rechecking the project use the same implementation.
- Studio previews affected occurrences before applying the changes to open
  buffers. Each file can be undone separately. It does not write to disk
  automatically. **Save all** now uses a private, hash-checked journal for
  atomic individual file replacement and rollback of interrupted batches
  (up to 16 files and 1 MiB per batch). File rename now tokenizes import paths,
  previews affected files, validates the complete moved project with the
  compiler, and applies source, destination, and import edits through a
  hash-checked journal (64-file/8-MiB transaction limit). Non-UTF-8 files and
  over-limit projects are rejected before changes.
- The LSP rename regression and F2 preview/apply passed in Chromium, Firefox,
  and WebKit. The browser test confirms the disk file remains unchanged until
  the user saves, then writes both files through the batch-save action.
- The JS bundle after this work measures 555,841 bytes, still over the 400 KiB
  target. `cargo test --workspace --locked` passes; two external database or
  backend fixtures are `ignored`.
- The extended file-rename/F2/Save-All browser flow passed in Chromium,
  Firefox, and WebKit. The targeted rename test, `cargo check --workspace
  --locked`, `cargo test --workspace --locked` (282 CLI unit tests; workspace
  tests passed, one MariaDB fixture test ignored), Clippy, formatting, UI
  metadata, and `git diff --check` passed. The current JS bundle is 556,424
  bytes, above the 400 KiB target. The browser regression also confirms that
  a previously open importer displays its updated content after the rename.
  Axe WCAG 2.2 A/AA and 360-, 768-, 1280-, and 1920-pixel viewport checks
  passed in Chromium, Firefox, and WebKit. The checks caught and led to fixes
  for an invalid tab-list role, dark-theme status-bar contrast, and light-theme
  success text contrast. Verification gutters now expose a group role instead
  of leaving focusable children inside an aria-hidden container. Axe ran at all
  four widths in both themes. 200% zoom remains untested.
- [x] The Studio visual baseline (1280 × 900, dark theme) was reviewed and
      accepted. Chromium checks later screenshots with a 0.2% changed-pixel
      allowance; Firefox and WebKit still run functional, viewport, and
      accessibility checks.

### Save All journal

- Save All validates every hash, path, duplicate, and total size before writing.
  A request accepts up to 16 files and 1 MiB of source.
- Before writes, Studio creates a mode-0700 directory under
  `.zelyra/studio-transactions/` with mode-0600 backups. A synced manifest and
  `prepared` marker precede file changes. Each file is replaced atomically. At
  startup, incomplete transactions are rolled back after hash checks; recovery
  stops on external edits instead of overwriting them.
- Targeted tests cover batch saves, conflicts before writes, and a simulated
  interrupted save. F2 plus Save All browser checks passed in Chromium,
  Firefox, and WebKit. Windows directory durability is not protected with the
  same `fsync` behavior; a real Windows runtime test is still missing.

- Compiler AST, type checker, verifier, and project loader remain authoritative.
  Studio and LSP obtain the same results from one service; regex text search is
  not a semantic reference or rename source.
- The HTTP token remains required for writes. The existing SSE event channel
  uses a header token and bounded versioned events; Host and Origin are checked
  exactly.
- Static file preview does not execute project code. A web application starts
  only through an explicit user action.
- PDF previews use the shipped PDF bytes. The 1.0.7 renderer produces
  searchable text PDFs, not CSS or image rendering.
