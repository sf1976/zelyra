# Zelyra 1.1.0 – Studio Deep-Native work log

## Objective and release boundary

Studio and `zelyra lsp` must use the same compiler-based language service.
Eight Studio tools, a secure event channel, recoverable multi-file changes, and
the existing single-binary distribution are acceptance requirements.
`v1.1.0-rc.1` is to be prepared. The request requires express authorization
before pushing a tag or publishing a GitHub release page.

Follow-up request on 15 October 2026: finish the Studio work first, then
verify five cited compiler gaps against code and close the actual gaps for
1.1.0. The user explicitly authorized publishing stable 1.1.0 after
successful acceptance. This supersedes the earlier no-publication boundary
for 1.1.0; release gates and verified artifacts remain mandatory.

Initial code inventory of the five items: user-defined payload enums with
exhaustiveness and generic structs are already implemented with positive and
negative tests (`runtime/src/tests.rs` around lines 511 and 969–1076). They
need regression review, not duplicate implementations. General string
interpolation, opt-in in-place array mutation, and a bytecode/AOT backend
appear absent in the initial search; define precise semantics and limits after
finishing the Studio modules. Claims such as “SQL injection is impossible” or
“99% of backends are complete” are not acceptance evidence and will not be
repeated as product guarantees.

Base: `origin/main` at `eaa57c3`, after `v1.0.7`; working branch
`feature/1.1.0-studio-deep-native`. The working tree had no user changes at
the start. This file records work and evidence; a checked box proves only the
specific scope stated beside it.

## Architecture and security decisions

- Compiler AST, type checker, verifier, and project loader remain authoritative.
  Studio and LSP obtain the same results from one service; regex text search is
  not a semantic reference or rename source.
- The existing HTTP token remains required for writes. The future event
  channel must support browser authentication without a long-lived URL token.
  Host and Origin remain exact checks.
- Static file preview does not execute project code. A web application starts
  only through an explicit user action.
- PDF previews use the shipped PDF bytes. The 1.0.7 renderer produces
  searchable text PDFs, not CSS or image rendering.
