# Zelyra 0.9.6 release plan

## Goal

Deliver an opt-in Laravel scaffold preview and a tenant-scoped notification center. Keep the release experimental and local-first. No notification provider, hosted service, or human acceptance is implied.

## Scope

- `zelyra migrate laravel <source> --report <path> --output <target>` may create both an analysis report and a separate Zelyra project. `--output` alone is allowed. The source remains read-only; no PHP, Artisan, `.env`, database, production data, secrets, or personal records are read or copied.
- Reject source/report/output overlap, symlink escapes, existing output targets, and unsafe paths. Write atomically and preserve file permissions conservatively.
- Generated files record the analyzer/ruleset version, source locations, and mapping IDs. A generated scaffold must clearly separate TODOs from transferred logic and pass the matching Zelyra compiler.
- Provide a tenant-scoped shared in-app notification feed with unread counts, expiry filtering, soft-delete archive, and editable preference records. This release does not claim per-user read receipts, scheduled retention deletion, or event-triggered email; those require recipient-aware delivery and are planned for 0.9.7.
- Every lookup must enforce tenant membership, including direct-ID routes. Missing tenant identity fails closed. The feed must work without SMTP configuration.

## Release gates

- [ ] Read-only migrator analysis remains byte-for-byte non-mutating; scaffold tests prove source, report, and target path separation.
- [ ] Path traversal, symlink escape, pre-existing targets, write failures, and interrupted generation are rejected without partial output.
- [ ] Generated output records source provenance and mapping-rule versions, labels every untransferred behavior, and passes `zelyra check`.
- [ ] MariaDB tenant-isolation tests cover list, unread count, archive filtering, expiry filtering, and guessed/forged cross-tenant notification IDs across two tenants.
- [ ] Authentication, membership, direct-ID authorization, pagination bounds, localization, archive, and expiry have positive and negative coverage.
- [ ] Per-user read receipts, scheduled retention, and event-triggered SMTP delivery remain explicitly deferred to 0.9.7, where atomic outbox enqueue, retry idempotency, and duplicate SMTP delivery must be tested.
- [ ] Accessibility, empty states, database/SMTP outages, localization, and bounded error messages are checked in Studio/browser flows.
- [ ] Notification-center database claims match actual tests; this slice is tested against MariaDB only, and that limit is visible in documentation.
- [ ] Full CI, dependency audit, generated-project checks, security review, and exact candidate artifact checks pass.
- [ ] Update English/German README, implemented matrix, release notes, roadmap, reference handbook, and the bilingual website handbook; regenerate Markdown/EPUB exports.
- [ ] Publish only after all gates above are complete; keep independent human product acceptance reserved for 1.0.0.
