# Zelyra 0.9.0 release plan: guided business workflows

**Status:** implementation merged into `main` at `407c81f8e75fa568797fc163d3416748214a6f19`.
The versioned candidate, exact CI, stable artifacts, handbook publication, and
branch cleanup are the remaining release-verification steps. Independent MFA
security review is a production gate before 1.0.0. Human product acceptance
remains reserved for 1.0.0.

The prepared [release notes](../release-notes/0.9.0.en.md) describe the
experimental scope and documented limits.

## User outcome

A developer can extend a small business application through guided tasks,
understand which generated files and routes change, and verify the result
against the real database servers Zelyra claims to support.

## Scope

- Extend the invoice tutorial into a coherent path through customer and item
  entry, dashboard, invoice creation, and linked invoice lines.
- In the studio, explain the impact of a guided change, show affected routes,
  files, tables, and relationships, and require explicit review before apply.
- Add compiler-backed examples for editing and extending generated Zelyra
  applications; generated output remains ordinary readable Zelyra source.
- Implement `zelyra text edit <plan.zedit>` for guided regex changes from a
  named TOML plan. Preview is the default; `--apply` requires the displayed
  plan ID, expected match counts, and unchanged input files. Follow the
  [design specification](../design/readable-regex-text-editing.en.md).
- Expand the 0.1 corpus with runtime semantics, error paths, modules/imports,
  effects, contracts, and SQL type fixtures.
- Run separately documented end-to-end workflows against the supported
  MariaDB, MySQL, and PostgreSQL server versions. State unsupported operations
  per backend rather than implying universal SQL behavior.
- Complete maintainer review and automated adversarial coverage for the
  generated CRUD, authorization, enabled tenant boundary, and transaction
  paths included here. Independent production security review remains a 1.0.0
  release gate.
- Preview: optional local TOTP for MariaDB projects with persistent sessions,
  an audit table, and an operator-managed 32-byte key. Enrollment, replay
  protection, recovery codes, throttling, and audit have integration coverage.
  This is not production security approval; that requires independent review
  before the 1.0.0 production release. MFA is not enabled for other database
  backends or external identity providers in 0.9.

## Release gates

- [x] From a clean project, complete the tutorial and test every generated step.
- [x] Cover create, read, update, and delete for the verified MariaDB tenant
  CRUD path, including missing permission, missing membership, forged tenant
  selectors, cross-tenant reads/writes, revocation, and rollback
  (`tests/mariadb-tenant-crud-e2e.sh`). Other backends remain limited to their
  separately published verified features.
- [x] Verify enrollment, guarded page and API access, sequential/concurrent
  TOTP and recovery-code replay, and the operator recovery procedure with
  audit retention through `tests/mariadb-mfa-e2e.sh`.
- [x] Verify the five-failure threshold, active lock rejection, stored
  15-minute expiry timestamp, and valid recovery after expiry through
  `tests/mariadb-mfa-e2e.sh`.
- [x] Verify the five-failure threshold, concurrent MFA replay protection,
  operator recovery, and the MariaDB version matrix for the implemented scope.
  Cross-process/key-restoration review, independent security review, and
  production readiness remain 1.0.0 gates.
- [x] Test that the editor preview matches the applied source and that compiler
  errors prevent applying invalid output.
- [x] Run the expanded language corpus and verify results are deterministic.
- [x] Publish the versioned database matrix and current evidence limits in
  `docs/database-support.en.md`.
- [x] Add bilingual 0.8.0 to 0.9.0 upgrade and rollback instructions under
  `docs/upgrades/`.
- [ ] The database matrix must pass for the exact version-bumped candidate.
  Independent MFA security review and production approval are mandatory 1.0.0
  gates; 0.9 labels MFA as a preview.

Optional external identity providers require a separate security review. A
general queue and full SQL portability are outside this scope. The bounded
MariaDB outbox published in 0.8 remains available.
