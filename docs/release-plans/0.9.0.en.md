# Zelyra 0.9.0 release plan: business workflows and optional local MFA

**Status:** implementation is present in the stacked 0.9.0 branch. CI, backend
integration coverage, independent security review, and operator recovery
rehearsal are release gates. This milestone remains pre-production.

## User outcome

A developer can extend a small business application through guided tasks,
understand which generated files and routes change, and verify the result
against supported database servers. Projects may also enable account-local
multi-factor authentication without depending on an external identity service.

## Guided business workflows

- Extend the invoice tutorial through customer and item entry, dashboard,
  invoice creation, and linked invoice lines.
- In the studio, explain the impact of a guided change and show affected routes,
  files, tables, and relationships before the developer applies it.
- Keep generated output as ordinary readable Zelyra source and prevent invalid
  compiler output from being applied.
- Expand the language compatibility corpus to runtime semantics, error paths,
  modules/imports, effects, contracts, and SQL type fixtures.
- Run documented end-to-end workflows against supported MariaDB, MySQL, and
  PostgreSQL server versions. State unsupported operations per backend.

## Optional local MFA

- Support TOTP enrollment after recent password confirmation and activate it
  only after a valid confirmation code.
- Require a valid TOTP code or one unused recovery code after password
  verification. An incomplete login session cannot access application routes,
  APIs, or session management.
- Generate high-entropy recovery codes, display them once, store only hashed
  verifiers, and consume each code atomically once.
- Encrypt TOTP secrets at rest with a documented operator-managed key and fail
  closed when the key is absent or invalid. Never log secrets, provisioning
  URIs, OTPs, or recovery codes.
- Persist replay prevention and bounded failed-attempt throttling. Require CSRF,
  same-origin checks, recent password confirmation, audit events, and session
  revocation for MFA setting changes.
- Keep MFA opt-in per project and document an administrator recovery procedure.

WebAuthn/passkeys, OAuth2/OIDC, external identity providers, mandatory MFA,
cloud dependencies, and general identity federation remain deferred.

## Release gates

- [ ] Complete tutorial steps from a clean project and test generated workflows.
- [ ] Cover supported CRUD, relationship, and negative authorization cases.
- [ ] Verify that studio preview matches applied source and compiler errors block
  invalid changes.
- [ ] Test enrollment, challenge, recovery, session restrictions, CSRF, same-origin
  checks, replay races, throttling, key loss, and secret-redacted diagnostics.
- [ ] Verify existing-user migrations with MFA disabled and rehearse operator
  recovery.
- [ ] Run the expanded deterministic language corpus and backend workflows.
- [ ] Complete independent security reviews of generated CRUD, authorization,
  tenant boundaries, database transactions, TOTP/recovery handling, and
  administrator recovery.
- [ ] Publish the exact database support matrix, known limitations, security
  review outcomes, and bilingual upgrade instructions.
