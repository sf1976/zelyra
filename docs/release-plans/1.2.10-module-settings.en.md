# Zelyra 1.2.10 — module settings and reusable packages

## Bounded outcome

Make the existing protected Studio module-settings page safe under concurrent
editor requests, and document the exact boundary between compiler-checked
package settings, local environment references, HostServices, and reusable CSV
packages.

This release does not add application-served configuration routes. A deployed
application must not receive implicit authority to rewrite its source-side
settings file. Authenticated in-app configuration remains a separate design
requiring an explicit authorization model and defined runtime reload behavior.

## Acceptance and limits

`zelyra module settings check` and package `module_setting<T>` retain their
existing compiler/runtime behavior. CSV import/export remain offline local
packages tested on AST, MIR, and Bytecode. HostServices remains a versioned
Rust embedding API, not a stable native ABI or a package plugin ABI.

The write mutex is scoped to a single Studio process. Run one Studio process as
the writer for `zelyra.settings.toml`; concurrent edits made by an unrelated
process are outside this transaction guarantee. Secret material continues to
come from the Zelyra process environment. ODBC, Excel, app-served settings
pages, and full backend parity remain scheduled for later releases through
1.3.0.
