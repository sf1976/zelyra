# Zelyra 0.99.0 final pre-acceptance release plan

**Status:** planned; feature freeze and technical readiness milestone. This
version is not approved for productive use. Independent human acceptance is
the sole remaining release gate before stable 1.0.0.

## Exit criteria

- [ ] Freeze language, CLI, project, runtime, editor, tutorial, and compatibility
  contracts. No new product features enter after this release.
- [ ] Pass the separate MariaDB, MySQL Server, and PostgreSQL server matrices
  for the workflows promised by 1.0.0. Record exact server versions, platforms,
  limitations, and reproducible CI evidence. A `mysql://` alias alone is not
  evidence of MySQL Server support.
- [ ] Complete security and dependency reviews, migrations, upgrade/rollback
  rehearsals, release artifact verification, SBOMs, attestations, and offline
  documentation checks.
- [ ] Verify the local studio and invoice tutorial against the frozen product
  scope. They must not require cloud accounts, telemetry, or external AI.
- [ ] Publish the technical 0.99.0 release and prepare an immutable
  `v1.0.0-rc.1` with matching documentation and human-study materials.
- [ ] Keep human acceptance open. Run it only against the exact immutable
  1.0.0 candidate; it is the remaining gate before stable 1.0.0.

The 0.99.0 release must not be described as human-accepted or productive.
If a technical gate is incomplete, 0.99.0 is not ready. If the human study
finds a blocker, fix it, publish a new candidate, and repeat affected tasks.

SQL Server, universal SQL portability, complete PostgreSQL parity outside the
tested matrix, mandatory cloud services, telemetry, and external AI providers
are not implied by this plan.
