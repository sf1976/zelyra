# Zelyra 1.2.16 work package: typed TableView row content

## User outcome

Business lists can show contextual text, links, and existing UI components
inside a selected cell, while actions can use identifiers or other explicitly
selected result fields without exposing those fields as extra table columns.

## Scope and semantics

- `view.row_fields { id ... }` explicitly selects result fields that are
  available to row templates but are not rendered as table columns.
- `view.column_content { item: row; column { html { ... } } }` attaches safe,
  compiler-checked content to a displayed column's cell.
- Both additions reuse the current typed template, component expansion,
  interpolation escaping, row scoping, and SQL validation. They add no routes,
  JavaScript actions, or write path.
- Search, filter, sort, and pagination continue to operate on their existing
  declared fields. Supplemental fields are only available to presentation
  fragments.
- The default table and existing row-action syntax remain compatible.

## Implementation plan and checkpoints

1. Extend AST/parser with bounded row-field and column-content declarations.
2. Validate names against the typed result record and displayed columns; reject
   forms and invalid field references.
3. Carry explicit supplemental fields through the query projection and render
   escaped values in the correct cells, preserving per-row/per-cell Dialog IDs.
4. Add compiler-checked example, positive/negative tests, bilingual UI docs,
   work log and roadmap updates.
5. Run targeted tests, workspace checks, documentation validation, and the
   applicable invoice/Tutorial checks before preparing a release.
