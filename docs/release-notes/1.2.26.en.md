# Zelyra 1.2.26

## Interactive language console

`zelyra console [main.zyl]` starts a compiler-checked AST REPL. Successful variables persist between inputs; final expressions print with `=>`. Syntax, type, and runtime failures do not end the session.

In a terminal, Reedline provides history in `~/.zelyra_history`, tab completion for functions, tables, records, and fields, and multiline continuation prompts. Piped input omits prompts.

The database sandbox uses one connection and a real MariaDB/MySQL transaction. Successful inputs release savepoints; failed runtime inputs roll back only their own database changes. The open transaction is rolled back on exit. `:commit` explicitly commits the current batch and starts a new sandbox transaction. `--persist` opts out of the sandbox.

Meta commands: `:help`, `:tables`, `:schema <table>`, `:tenant <id>`, `:commit`, `:rollback`, `:clear`, `:quit`, and `:exit`.

## Limitations

- PostgreSQL sandbox transactions are not implemented.
- Only the AST interpreter is supported; `--backend bytecode` is rejected with a clear diagnostic.
- `--tenant` exposes `tenant_id` in the REPL scope but does not add automatic tenant filtering.
- Without a configured project connection, only expressions without database access are available.
