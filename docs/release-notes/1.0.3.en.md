# Zelyra 1.0.3

Zelyra 1.0.3 brings together expanded built-in standard functions, the typed pipeline operator `|>`, flat `else if` cascades, and improvements to Studio and the invoice tutorial.

## 1. Expanded Standard Library

The new stateless functions can be called directly. Pipeline stages are type checked; access to external resources still requires the appropriate capability:

1. **Mathematics & Numerics:** `abs`, `min`, `max`, `clamp`, `sqrt`, `pow`, `floor`, `ceil`, `round`
2. **Strings & Text Processing:** `len(String)`, `text_to_lower`, `text_to_upper`, `text_starts_with`, `text_ends_with`, `text_replace`, `text_split` (alias: `split`), `text_pad_left`, `text_pad_right`, `text_index_of`, `text_repeat`, `text_is_empty`, `text_is_blank`, `text_capitalize`, `text_substring`, `text_trim_start`, `text_trim_end`
3. **Arrays & Collections:** `sort`, `sort_desc`, `reverse`, `slice`, `concat`, `join`, `unique` (alias: `dedup`), `array_sum`, `avg`, `min_of`, `max_of`, `chunk`, `flatten`, `zip`
4. **Sets:** `set_union`, `set_intersection`, `set_difference`
5. **Maps & Iteration:** `get_or` (`get_or_default`), `has_key`, `map_remove`, `map_merge`, `map_increment`, `entries` (returns key-value tuples that `for` loops can type check and destructure)
6. **Date & Calendar Arithmetic:** `date_add_days`, `date_diff_days`, `is_before`, `is_after`
7. **Control Flow & Error Handling:** `is_ok`, `is_err`, `is_some`, `is_none`, `unwrap_or`, `panic`
8. **Type Conversions & Parsing:** `to_string`, `parse_int`, `parse_float`, `to_int`, `to_float`, `parse_bool`
9. **Security & Web Encodings:** `hash_sha256`, `base64_encode`, `base64_decode`, `url_encode`, `url_decode`, `uuid_v4` (`uses Random`)
10. **Paths & Filesystem:** `path_join`, `path_filename`, `path_extension`, `path_dir` (pure path operations without capability); `file_exists`, `dir_exists`, `file_size` (`uses FileSystem`)

Math functions check overflow and their defined domains. `round` rounds halfway cases away from zero and accepts decimal places from `-15` to `15`. Text lengths, padding, and search positions count Unicode code points; generated padding and repeated text are limited to 16 MiB.

## 2. Forward Pipeline Operator `|>`

Zelyra now supports the forward pipeline operator `|>`. Expressions flow from left to right through transformation chains without deeply nested parenthesized function calls:

~~~zelyra
cleaned = "  customer@example.com  "
    |> text_trim()
    |> text_to_lower()
~~~

## 3. Flat `else if` Branching

Conditional branches now support flat `else if` chains without mandatory nested blocks:

~~~zelyra
if status == 1 {
    return "Active"
} else if status == 2 {
    return "Paused"
} else {
    return "Inactive"
}
~~~

## 4. Zelyra Studio & Database Robustness

- **Declared Schema Fallback when Database is Offline:** If the local MariaDB service is not yet started or the database is not created, Studio no longer crashes with a 502 error. All tables declared in Zelyra source code (`main.zyl` and imported modules) are listed as *declared in source · missing in live DB*.
- **Automatic Schema Initialization:** When creating the database in Studio, the local Docker Compose service is started if needed, and the schema is initialized immediately.
- **Free local ports:** New projects select available web and MariaDB ports. If Compose still reports a conflict at startup, Zelyra retries with a bounded number of free ports, updates the managed `.env` and local database address, and reports the address that is actually reachable. Explicit process environment overrides remain authoritative.
- **Invoice sample data:** The invoice tutorial loads two customers, three items, one draft invoice, and two invoice lines. CLI setup and Studio Run load the marked seed repeatably without duplicating records.
- **Bounded recursion:** More than 20 nested function calls return a controlled runtime error before exhausting a small thread stack.

## 5. Formatter, Robustness, and Verification

- `zelyra fmt` formats pipeline operators and `else if` blocks consistently and idempotently.
- The invoice application was started separately through the CLI and Studio Run. Both previews returned HTTP 200 with sample data, and rerunning the seed did not create duplicates.
- Focused runtime tests check math overflow and domain errors, conversion boundaries, Unicode indexes, and safe text padding. Full release checks must be rerun against the final 1.0.3 commit.
