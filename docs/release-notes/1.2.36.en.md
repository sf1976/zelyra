# Zelyra 1.2.36

Typed CRUD actions that pass a generated guard now reuse one AST interpreter
and one derived program context for both the guard and its handler. A rejected
guard still prevents the handler from running. The guard's capability-limited
execution and the request owner's SQL transaction remain unchanged. This avoids
rebuilding runtime context between the two stages; no performance gain is
claimed without a benchmark.

## Verification

- `cargo clippy -p zelyra-runtime -p zelyra-web --all-targets --locked -- -D warnings`
- MariaDB and PostgreSQL typed CRUD action end-to-end tests
- Full GitHub CI and release artifact checks are required before publication.
