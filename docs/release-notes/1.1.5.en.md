# Zelyra 1.1.5

Zelyra 1.1.5 completes the first local, reusable package workflow for projects
that need shared, statically checked business code.

- Local packages are declared by path and version in `zelyra.toml`, imported
  explicitly as `pkg:<dependency>`, and locked offline in `zelyra.lock`. The
  lock covers package manifests and source files with SHA-256 checksums.
- Package manifests can bound declared effects and state the compatible Zelyra
  CLI range. Type, visibility, dependency-cycle, capability, and compatibility
  checks remain active across package boundaries.
- `zelyra module init` creates an offline package scaffold with a typed public
  example, compatibility metadata, no declared effects, and usage instructions.
  It refuses to overwrite existing destinations.
- `zelyra module list`, `module plan`, and `module bundle` expose checked
  dependency information and produce reviewed local source bundles. Typed
  package settings can be checked with `module settings check`; Studio can edit
  project-local settings with revision checks while keeping secret values out
  of responses and logs.
- The business-module examples include reusable CSV import and export packages.
  The bounded CSV importer validates headers and row widths; it does not write
  to a database.

Package checks and program execution can remain offline after local
installation. Separately published transitive dependencies, signed registry
packages, module settings pages for
ordinary applications, ODBC, Excel export, graphical PDF workflows, and
complete backend parity remain roadmap work. Package code is executable source
and still requires review and normal application capabilities. CSV input is
limited to 16 MiB and processed in memory. AST remains the default execution
backend; MIR and Bytecode are opt-in experimental subsets.

The repository and package examples use Zelyra 1.1.x. The language
compatibility line remains `0.1`.
