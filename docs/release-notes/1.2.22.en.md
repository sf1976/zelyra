# Zelyra 1.2.22

Zelyra 1.2.22 adds generated master-detail CRUD forms for business records
with direct child collections.

## Master-detail CRUD

Declare one `has_many` relation inside a CRUD definition to generate child rows
on its Create and Edit forms. The compiler checks the child model, foreign key,
sort field, delete behavior, and numeric aggregate expressions. Child IDs,
foreign keys, tenant keys, and sensitive fields are not accepted as editable
form data.

Parent and child changes, child table invariants, and server-computed
aggregates are applied in one transaction. Failed child validation or a failed
write rolls the operation back. Edit loads existing rows and replaces the
collection atomically. Rows are server-rendered and work without JavaScript.

The initial implementation supports one direct child collection per CRUD and
up to 50 rows per submission. Nested collections and multiple child
collections are not supported. The line-item editor replaces the submitted
collection on Edit; it is not a per-row patch API.
