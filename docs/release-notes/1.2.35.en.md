# Zelyra 1.2.35

This release preserves Laravel unsigned integer storage widths in generated
Zelyra schemas. The compiler checks the `unsigned_storage` table modifier while
keeping `UInt`, `Id`, and relation value types unchanged. Imported Laravel
`id()`, `foreignId()`, and `unsignedTinyInteger()` through
`unsignedBigInteger()` declarations retain their width in source and report
metadata.

MariaDB DDL uses the matching native `UNSIGNED` integer type. Read-only schema
inspection now reads full column type metadata, including signedness, and
normalizes legacy display widths without confusing distinct integer widths.
Automatically generated IDs and relation columns retain compatible native
types on PostgreSQL and SQLite; ordinary `UInt` columns use `NUMERIC(20,0)` on
those backends.

The modifier changes database storage only. It does not narrow the Zelyra
`UInt` type, so a narrower physical column can reject values the language type
permits. PostgreSQL and SQLite do not provide MariaDB's per-width unsigned
range constraints. Signed Laravel integer widths and full Laravel schema
parity remain outside this release.


The release also preserves Laravel `mediumText` and `longText` capacity in
selected generated MariaDB schemas through the compiler-checked
`text_storage medium|long` column modifier. MariaDB emits `MEDIUMTEXT` or
`LONGTEXT` and rejects unsupported indexes on these unbounded columns.
PostgreSQL and SQLite use native `TEXT`; their backend-specific size limits
remain different and are reported by the importer. This preserves source
capacity for supported MariaDB fields; it does not complete Laravel website
behavior migration.
