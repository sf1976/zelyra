# Zelyra 0.7.0

Zelyra 0.7.0 ergänzt Zelyra Studio, ein geführtes Rechnungstutorial, eine
begrenzte MySQL-Runtime und den ersten experimentellen mandantenbewussten
CRUD-Pfad. Das Release bleibt experimentell und ist nicht für den
Produktiveinsatz freigegeben. Die menschliche Abnahme ist für 1.0.0 vorgesehen.

## Zelyra Studio

`zelyra editor [directory] [--port <port>]` startet einen lokalen Browsereditor
auf `127.0.0.1`. Studio enthält Projektdateibaum, Tabs, Syntaxfarben,
Suche/Ersetzen, Zelyra-Schlüsselwortvervollständigung, Speichern mit
Konfliktschutz, neue Dateien, Compilerdiagnosen und explizite Formatierung.
Dateien sind auf 1 MiB begrenzt. Versteckte Dateien, Secrets, generierte
Verzeichnisse und Symlinks sind ausgeschlossen. Schreibzugriffe benötigen ein
zufälliges Sitzungstoken und denselben Browser-Origin. Der Editor führt keine
Shellbefehle aus und sendet keinen Quelltext an externe Dienste.

Studio ist ein lokales Entwicklungswerkzeug, keine vollständige IDE. Ein
visueller Datenbankbrowser und ein CRUD-Assistent gehören nicht zu diesem
Release.

## Geführtes Rechnungstutorial

`zelyra --tutorial invoice` führt im Terminal in kurzen, wiederholbaren
Schritten durch Kundenerfassung, Artikelerfassung, Dashboard und
Rechnungserstellung. Jeder erzeugte Stand lässt sich prüfen; das Tutorial
ersetzt keine Produktionsprüfung oder Betreiberkonfiguration.

## Begrenzte MySQL-Runtime

Der geprüfte MySQL-Umfang umfasst parametrisierte, typisierte SQL-Abfragen auf
MySQL Server 8.4.11. Schema- und Administrationsbefehle brechen mit
`E-DB-019` ab. Migrationen, generierte CRUD-/Web-Routen und Authentifizierung
über MySQL sind nicht enthalten. Daraus folgt keine allgemeine MySQL-
Kompatibilitätszusage.

## Experimenteller Mandanten-CRUD-Pfad

Auf MariaDB kann eine generierte CRUD-Routenfamilie eine ausdrücklich
mandantengebundene Tabelle verwenden. Die Runtime bindet die Identität an eine
geprüfte Datenbanksitzung, prüft Memberships pro Request, behandelt Header- und
URL-Werte nur als Selektoren und beschränkt generierte Lese- und
Schreiboperationen auf den ausgewählten Mandanten. Die Implementierung ist
absichtlich auf eine Tabelle begrenzt.

Dieses Feature ist keine vollständige Multi-Tenancy. Es unterstützt keine
mandantenbewussten Migrationen oder Backfills, Beziehungen, eigenen SQL-
Aktionen, TableViews, Exporte oder PostgreSQL-/MySQL-Tenant-Runtime. Bestehende
Datensätze werden nicht automatisch einem Mandanten zugeordnet. Tenant-Daten
sollten nur mit ausdrücklich geprüftem Schema und Zuordnungen verwendet werden.

## Einrichtung und Tests

`zelyra setup` diagnostiziert einen wahrscheinlich falsch geschriebenen
absoluten Pfad wie `/projekt`, wenn stattdessen `./projekt` existiert. Für ein
minimales `zelyra init`-Projekt erklärt die Fehlermeldung, dass Datenbank-Setup
ein MariaDB-Projekt benötigt.

Die Sprachkompatibilitätslinie `0.1` bleibt unabhängig von der Compiler-Version.
Ein erstes ausführbares Korpus prüft akzeptierte und abgewiesene Programme,
Diagnosecodes, Laufzeitausgabe und Formatierung. Es ist noch kein vollständiger
Konformitätsnachweis für 1.0.0.

## Reifegrad und Grenzen

0.7.0 ist experimentell und nicht für den Produktiveinsatz freigegeben. Das
Release behauptet weder vollständige PostgreSQL-Parität noch universelles SQL,
vollständige Multi-Tenancy, eine vollständige IDE oder eine allgemeine formale
Verifikation. Die unabhängige menschliche Abnahme wird erst für den
unveränderlichen 1.0.0-Kandidaten durchgeführt.

Prüfnachweise und verbleibende technische Grenzen stehen im
[Releaseplan 0.7.0](../release-plans/0.7.0.de.md) und im
[Mandanten-Bedrohungsmodell](../release-readiness/0.7.0-tenant-threat-model.de.md).
