# Zelyra 1.2.7

Zelyra 1.2.7 ergänzt signierte, separat veröffentlichte Paketabhängigkeiten.

## Transitive Registry-Pakete

Ein signiertes Paket kann eine exakte Registry-Abhängigkeit deklarieren:

```toml
[dependencies.text]
registry = "https://pakete.example.test/index.json"
name = "text"
version = "=1.4.2"
```

`zelyra package add` und `zelyra package update --plan <datei.toml>` lösen den
vollständigen Abschluss auf. Jedes Paket muss mit dem passenden Indexeintrag
übereinstimmen und von einem ausdrücklich im Trustfile freigegebenen
Ed25519-Schlüssel signiert sein. Zyklen, widersprüchliche Quellen,
Hashabweichungen und nicht vertraute Herausgeber werden vor der Manifest-
Umschaltung zurückgewiesen. Der Abschluss ist auf 128 Artefakte, 256 MiB
Download und fünf Minuten begrenzt.

Der Installer protokolliert Cache- und Stagingpfade im Recovery-Journal. Nach
dem Staging prüft der Compiler das vollständige Projekt; Fehler führen zum
Rollback. Herkunftsdaten für jede Paketversion stehen im Lockfile v2 und in
`[package_provenance."name@version"]` des Projektmanifests. Pakete und ihre
signierten Manifeste bleiben unverändert.

Nach Installation funktionieren `zelyra check`, `zelyra run` und
`zelyra module bundle` ohne Registryverbindung. `package sign` bleibt offline;
bei Registry-Abhängigkeiten wird die vollständige Compilerprüfung deshalb erst
nach Signatur- und Trustprüfung während der Installation durchgeführt.

## Prüfung

Die Integrationstests prüfen eine dreistufige Registry-Kette mit Add, Run,
Offline-Check, Bundle und Updateplan sowie die Ablehnung eines Zyklus ohne
Änderung am Manifest oder Paketcache. Die übrigen Workspace- und Release-Gates
werden im Release-Workflow ausgewiesen.
