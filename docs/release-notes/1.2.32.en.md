# Zelyra 1.2.32 — computed business fields and secure CRUD attachments

Zelyra 1.2.32 adds compiler-checked calculated fields and connects private
FileRef storage to generated CRUD forms. Together with the number series
published in 1.2.31, this covers the five reported business CRUD findings.

## Computed business fields

Table columns can declare a checked expression:

```zelyra
table invoice_items {
    quantity: Decimal(10, 2) required
    unit_price: Decimal(12, 2) required
    total: Decimal(12, 2) required compute(quantity * unit_price)
}
```

The compiler validates field dependencies, result types, cycles, and
unsupported expressions. Generated CRUD forms and supported validated API
POST/PUT/PATCH mutations recompute the value on the server. Submitted values
for computed fields are ignored. For partial API updates, omitted input fields
are merged from the existing tenant-checked record before validation and
computation.

Decimal results are rounded to the declared scale, with half values rounded
away from zero. Overflow is rejected. No browser preview is treated as the
authoritative computation.

## FileRef attachments in generated CRUD

Declare upload constraints on a `FileRef` column with `attachment`:

```zelyra
table contracts {
    id: Id primary auto
    title: String(200) required
    signed_pdf: FileRef? attachment {
        max_size: "20MB"
        allowed_types: ["application/pdf"]
    }
}

crud Contract -> contracts {}
```

Generated create and edit pages use a native file input. Omitting a replacement
file on edit retains the current reference. Replacements use the existing
private, integrity-checked storage and are published through the existing CRUD
action. Lists and details show protected download links instead of raw
references. Every download rechecks permissions, record, and tenant. Rollback
removes only staged bytes.

The `attachment` block uses the existing size policy and PDF, PNG, and JPEG
allowlist. The existing aggregate request limit still applies. Storage
creation is currently supported on Unix only.

## Tenant isolation and localization

Generated master-detail legend tokens are resolved after HTML escaping. Tests
cover built-in fallbacks, project translations, and the absence of internal
tokens from rendered HTML.

Number series from 1.2.31 remain available. Counters are isolated by series
and verified tenant, but numbering is not gapless.

## Laravel importer

The importer can preserve a narrowly recognized static boolean account
approval guard as `login_enabled` in a native Zelyra auth declaration. It does
not copy Laravel accounts, password hashes, or secrets. Administrator
exceptions, registration, tenant selection, MFA, and controller-specific
messages remain manual migration findings.

## Verification

- Workspace tests, Clippy, formatting, and release metadata validation.
- MariaDB/PostgreSQL tests for computed CRUD/API mutations, partial updates,
  tenant isolation, and number series.
- MariaDB HTTP and Chromium tests for upload, retention and replacement,
  rollback cleanup, FileRef redaction, and cross-tenant download denial.
- Laravel auth importer E2E using a minimal fixture and disposable MariaDB;
  `/opt/siedelmann-laravel/app` was inventoried read-only and not modified.

## Limits

Computed expressions are restricted to the documented pure subset. No live
browser calculation preview is provided. Runtime and bytecode parity continues
to be verified separately through 1.3.0. The database and file store still
require separate backups as documented; no crash-atomic combined backup is
provided.
