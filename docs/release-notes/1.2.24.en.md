# Zelyra 1.2.24

Generated CRUD Create and Edit forms can now manage multiple direct `has_many`
collections on the same parent record. Each collection renders in its own
section, has an independent row count, and uses namespaced field and row-action
names.

Zelyra validates every collection before writing. Parent data, all child rows,
and declared aggregate recalculations are committed in one database
transaction. An invalid collection or a database error rolls back the complete
operation. Editing locks and reads the existing child rows for the selected
parent, then replaces only that parent's rows. Tenant identity continues to
come from the verified request context.

The existing per-collection limit of 50 rows remains in force. A child table
can be attached only once to a CRUD resource, and aggregate targets cannot be
assigned ambiguously by multiple collections.

See [`examples/multiple_children/main.zyl`](../../examples/multiple_children/main.zyl)
for a compiler-checked invoice example with line items, attachments, and
aggregates.
