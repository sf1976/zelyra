# Zelyra 1.0.7

**Release:** `v1.0.7` · **Language compatibility:** `0.1`

Zelyra 1.0.7 expands the language and runtime for verifiable business logic
and adds local server-side text-PDF rendering for views and transactional
email attachments.

## Language and compiler

- `if` can return a checked value. Records can be copied and selectively
  updated with `Customer { ..old, active: true }`.
- Lexical lambdas work with `map`, `filter`, `find`, and `reduce`; callback
  input and output types are checked statically.
- `match` supports nested record patterns and boolean guards. A guarded arm
  alone does not prove exhaustive coverage.
- Contextual field names such as `version` and `type` are allowed in records.
  Tuples can be ordinary function results and can be destructured outside
  loops.
- `[runtime] max_stack_depth` accepts values from 1 to 500; the default
  remains 20. `zelyra run file.zyl --max-steps N` bounds statements and
  expression evaluations across all `parallel` branches and reports an
  exceeded budget as `E-RUNTIME-001` at the source location.
- `type OrderId = Id` remains nominal and does not accept an ordinary `Int`
  literal. Use `type OrderNumber = Int` for a business-number alias.
- API error payloads require `output Result<T, E>` with a matching `E`.
  Transactions can be checked offline but require an active database runtime
  when executed.
- An `auth` block registers the existing login, logout, session, reset, MFA,
  and configurable admin handlers. `zelyra routes` lists the actual available
  HTTP methods and paths; optional tables and settings determine optional
  routes. CRUD permissions remain enforced server-side.
- Omitted named view slots render their fallback. `parallel` waits for its
  `await` bindings at the end of the block and makes checked values available
  in the enclosing scope.

## Server-side PDF and email attachments

`render_pdf("InvoicePrint", invoice)` renders a declared view locally into
`Bytes`. Record placeholders are escaped; `for item in collection` evaluates
record arrays. Inside the same database transaction, `mail_queue` can store a
PDF attachment in the MariaDB outbox.

The renderer produces paginated, searchable text PDFs. HTML input and expanded
output are each limited to 2 MiB, collection blocks to 10,000 record rows, and
documents to 200 pages. The PDF does not reproduce CSS layout, images, colors,
typography, SVG charts, or precise table geometry. Use the browser print view
for graphical, layout-faithful documents. Delivery uses the existing
explicitly started outbox worker; no background delivery starts implicitly.
