# Zelyra 1.1.1

Zelyra 1.1.1 fixes misleading Studio messages while opening and running local
web projects.

- A browser that closes a local Studio request no longer produces a noisy
  `Broken pipe` error.
- The successful `Zelyra server listening` message is written to standard
  output and appears as informational `preview.stdout` in Studio Logs.
- `zelyra serve` binds a free local port if its requested port is already in
  use and prints the actual address. `zelyra doctor` treats a busy requested
  port as a warning when this fallback is available.
- Canvas now clearly says that it only renders a static inspection preview.
  To run routes and handlers, use **Start** in Studio and then **Open
  application in browser**. The Canvas sandbox remains enabled.
- Docker Compose port fallback also remains available: if a generated
  project's web or MariaDB host port is occupied, setup retries with a free
  port and updates the local project configuration.
- If the Outbox cannot load because MariaDB is unreachable or its table is not
  initialized, Studio now explains both likely causes, gives the setup command,
  and says the message can be closed when the project does not use Outbox.

This patch does not change the language compatibility line or require Node.js,
npm, or a browser-side runtime installation for released Zelyra applications.
