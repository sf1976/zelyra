# Zelyra 1.6.0 — Financial & Temporal Integrity (`Money<C>`, `ledger`, `auditable` & EN 16931)

## Currency-Safe `Money<Currency>`

Monetary values carry their currency in the static type — mixing currencies is now a hard compile-time error:

```zyl
net = money<EUR>("100.00")
tax = money<EUR>("19.00")
gross = net + tax                              // Money<EUR>
usd = convert_money<EUR, USD>(gross, decimal("1.10"))  // explicit half-even conversion
// net + usd -> Compile error: cannot mix currencies `Money<EUR>` and `Money<USD>`
```

- Supports ISO-4217 currency tags (`EUR`, `USD`, `CHF`, `GBP`, `JPY`, `CAD`, `AUD`, `SEK`, `NOK`, `DKK`, `PLN`, `CZK`) as well as user-defined currency types.
- Exact `Decimal` arithmetic with zero floating-point rounding drift (at most 4 fractional digits in `money<C>`).

## Append-Only `ledger` (`E-LEDGER-001`) & Bitemporal `auditable` Tables

```zyl
ledger journal_entries {
    id: Id primary auto
    journal_id: Id required
    account: String(64) required
    debit: Decimal(12, 2) required
    credit: Decimal(12, 2) required
}

table contracts auditable {
    id: Id primary auto
    title: String(120) required
}
```

- **Compile-time immutability (`E-LEDGER-001`):** Any SQL `UPDATE` or `DELETE` targeting a `ledger` table (across functions, tests, workflows, forms, and CRUD actions) is rejected at compile time.
- **Zero-sum verification:** `verify_ledger_balance(debits, credits)` checks `sum(debit) == sum(credit)` with exact decimal arithmetic across AST, MIR, and Bytecode v30.
- **Bitemporal metadata:** `table <name> auditable` automatically synthesizes `valid_from`, `valid_to`, `recorded_at`, and `recorded_by` in the generated schema; `zelyra reflect --format=json` exports `is_ledger` and `is_auditable`.

## Typed EN 16931 E-Invoicing (`einvoice_xml` & `einvoice_validate`)

- `einvoice_xml(invoice_number, issue_date, currency, seller_name, buyer_name, net_total, tax_total, gross_total)` generates escaped EN 16931 `CrossIndustryInvoice` XML (`urn:cen.eu:en16931:2017`) while enforcing `net_total + tax_total == gross_total`, ISO date format, and 3-letter uppercase ISO currency codes.
- `einvoice_validate(xml)` validates structure, EN 16931 profile URN, monetary summation consistency, and rejects `<!DOCTYPE`/`<!ENTITY` for XXE protection.

## Honest Scope Notes

- Transactional `post_ledger { ... }` blocks with hash chains, `zelyra ledger verify`, `AS OF` time-travel SQL syntax, and PDF/A-3 embedding in the mail outbox build on this 1.6.0 foundation and are not claimed as already shipped.
- AST remains the default execution path; MIR and Bytecode v30 remain opt-in.
