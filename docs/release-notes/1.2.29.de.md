# Zelyra 1.2.29 — sichere Datei-Uploads

Zelyra 1.2.29 ergänzt begrenzte Multipart-Uploads für geprüfte Formulare.
Ein Formular kann ein Datei-Feld mit Maximalgröße und einer begrenzten
Medientyp-Auswahl deklarieren. Der Server prüft Dateisignatur und Größe,
speichert akzeptierte Inhalte außerhalb des öffentlichen Verzeichnisses unter
einer opaken, mandantengebundenen Referenz und stellt sie über eine
authentifizierte CRUD-Downloadroute mit Berechtigungsprüfung bereit.

Der Upload-Ablauf erhält Routenberechtigungen, CSRF-Prüfung,
Formularvalidierung, Datenbankparameterbindung und Bereinigung bei
Transaktionsfehlern. Unterstützt wird eine Datei pro Feld mit PDF-, PNG- oder
JPEG-Signatur. Beim Ersetzen wird die vorherige Datei erst nach Commit der
Datenbanktransaktion entfernt. Beim endgültigen Löschen eines Datensatzes wird
eine Datei nur entfernt, wenn keine deklarierte `FileRef`-Spalte mehr auf sie
verweist. Soft-Delete bewahrt die Datei.

`zelyra files cleanup` zeigt alte, nicht referenzierte Dateien und verwaiste
Staging-Paare zunächst nur in einer Vorschau. Löschen erfordert ausdrücklich
`--apply --maintenance-window`; der Befehl prüft Datenbankreferenzen erneut
während einer exklusiven lokalen Wartungssperre. Upload-fähige Server halten
während des Betriebs die zugehörige gemeinsame Sperre. `zelyra files backup`
und `zelyra files restore` erstellen und prüfen einen privaten Snapshot des
Dateispeichers mit SHA-256-Prüfsummen.

## Grenzen

Die verwaltete Speicheranlage schlägt auf Nicht-Unix-Plattformen derzeit
geschlossen fehl, da private ACL-Unterstützung fehlt. Unterstützt werden nur
PDF, PNG und JPEG und eine Datei pro Feld. Signaturprüfungen bereinigen keine
Dokumente und scannen sie nicht auf Schadsoftware. Ein Prozessabsturz zwischen
Dateiveröffentlichung und Datenbank-Commit kann eine unerreichbare verwaiste
Datei hinterlassen; die ausdrückliche referenzgeprüfte Bereinigung behandelt
diesen Fall. Dateispeicher-Backups enthalten keine Datenbankinhalte,
Projektkonfiguration oder Geheimnisse; diese müssen separat und bei gestoppten
Zelyra-Servern gesichert werden. Ein koordiniertes Gesamtbackup ist nicht
enthalten. Der Laravel-Importer kennzeichnet nicht unterstützte Uploadabläufe
für eine manuelle Migration; beliebige Laravel-Uploadlogik wird durch dieses
Release nicht importiert. Der vollständige Upload-Lebenszyklus wurde nicht für
PostgreSQL end-to-end geprüft; dafür wird keine Unterstützung behauptet.
