# Zelyra 1.2.7

Zelyra 1.2.7 adds signed, separately published package dependencies.

## Transitive registry packages

A signed package can declare an exact registry dependency:

```toml
[dependencies.text]
registry = "https://packages.example.test/index.json"
name = "text"
version = "=1.4.2"
```

`zelyra package add` and `zelyra package update --plan <file.toml>` resolve the
complete closure. Every package must match its registry index entry and use an
Ed25519 key explicitly trusted in the project trust file. Cycles, conflicting
sources, digest mismatches, and untrusted publishers are rejected before the
manifest switch. A closure is limited to 128 artifacts, 256 MiB downloaded,
and five minutes.

The installer journals cache and staging paths. After staging, the compiler
checks the complete project; failures roll back. Provenance for every package
version is recorded in lockfile v2 and in `[package_provenance."name@version"]`
in the project manifest. Packages and their signed manifests are not rewritten.

After installation, `zelyra check`, `zelyra run`, and `zelyra module bundle`
work without a registry connection. `package sign` remains offline; for
registry dependencies, full compiler validation therefore occurs during
installation after signature and publisher-trust checks.

## Verification

Integration tests cover a three-level registry chain with add, run, offline
check, bundle, and update-plan flows, plus cycle rejection without changing the
manifest or package cache. The remaining workspace and release gates are
reported by the release workflow.
