# Zelyra 1.5.0 — Living Business Processes (`states` v2, `four_eyes` & `workflow`)

## Enhanced State Machines (`states` v2) & Native Four-Eyes Principle (`four_eyes`)

Declarative `states` blocks now support per-transition role requirements and native four-eyes separation of duties, composable with `when` guards on the same transition line:

```zyl
table purchase_orders {
    id: Id primary auto
    created_by: Id required
    total_amount: Decimal(12, 2) required
    status: String(24) default "draft"

    states status {
        draft -> submitted
        submitted -> approved requires role("approver"), four_eyes(created_by) when total_amount > decimal("0") : "Amount must be positive."
        submitted -> rejected requires role("approver")
        approved -> final
        rejected -> final
    }
}
```

- **Static schema validation:** The compiler verifies that the column referenced by `four_eyes(<column>)` exists on the table, is not the state column itself, and has an identity-compatible type (`Id`, `Uuid`, `Int`, `UInt`, or `String`).
- **Fail-closed runtime enforcement under `SELECT ... FOR UPDATE`:** On every CRUD state transition, the web runtime enforces required roles and compares the verified session identity against the creator column, rejecting self-approvals, missing roles, unauthenticated actors, and missing creator values under transaction rollback.

## Declarative Workflows (`workflow`), Timer Rules & Sagas

New top-level `workflow` blocks bind timer rules (`after`), entry hooks (`on enter`), and compensation hooks (`compensate`) directly to a typed `states` column:

```zyl
workflow PurchaseApproval on purchase_orders.status {
    after 72h in submitted -> escalate_order
    on enter approved {
        notify_approved()
    }
    compensate on rejected {
        release_budget()
    }
}
```

- **Static type & capability checking (`E-WORKFLOW-001`):** Target table, state column, states, legal timer transitions, handlers, and explicit `uses` capabilities on hook bodies are statically verified by the compiler.
- **Formal process verification (`zelyra verify`):** `ContractKind::Workflow` statically detects timer-driven state cycles (e.g. `pending -> retrying -> pending`) and reports them as `FAILED`; acyclic workflows are reported as `PROVEN` alongside transparent counts of runtime-enforced `four_eyes` and role-gated transitions.

## Process Diagrams, Reflection & LSP

- **`zelyra doc <file.zyl> --workflows`** (and enhanced `--states`): emits deterministic Mermaid `stateDiagram-v2` diagrams including `[role: ...]`, `[four-eyes: <col>]`, `[guarded]`, `[after <dur>]`, and hook notes.
- **`zelyra reflect --format=json`:** exports `required_roles` and `four_eyes_column` on each state transition plus the deterministically sorted top-level `workflows` array.
- **`zelyra lsp`:** surfaces `workflow` declarations in document/workspace symbols, enriches table hover with `[role: ...]`/`[four-eyes: ...]` and bound workflows, and adds completions for `workflow`, `four_eyes`, `after`, and `compensate`.

## Honest Scope Notes

- Child-aggregate predicates inside `when` guards (`count(items) > 0`) and automatic background dispatch of `after` timers / `on enter` hooks via the resident scheduler worker build on this compiler-checked model and are not claimed as automatically dispatched in the background yet.
- AST remains the default execution path; MIR and Bytecode v30 remain opt-in.
