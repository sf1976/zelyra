# Zelyra 0.8.0

**Status: experimental, not approved for production use.** Independent human
acceptance for earlier versions remains open until 1.0.0.

Zelyra 0.8.0 expands local Studio with an interactive database schema map and a
guided CRUD source builder. It also adds a bounded MariaDB outbox and expands
the language compatibility corpus for line 0.1.

## Zelyra Studio

- The relationship map shows tables and foreign keys. Tables, columns, types,
  nullability, keys, and differences between declared and live schemas are
  visible.
- Live introspection is available for the tested MariaDB and PostgreSQL paths.
  MySQL live introspection is explicitly reported as unsupported; this is
  separate from the typed MySQL queries added in 0.7.0.
- The CRUD builder offers only declared, live tables and source files imported
  by the project entry. It shows generated Zelyra code, a diff, and compiler
  diagnostics.
- Preview does not modify project files. Changes are written atomically only
  after explicit apply and a fresh hash check. Source files and database schema
  still require separate saving or migration; Studio does not change records.
- The local editor remains a development tool, not a complete IDE or arbitrary
  database designer. See the [Studio guide](../studio.en.md).

## Bounded MariaDB outbox

`zelyra outbox setup`, `list`, `requeue`, and `run` explicitly manage an
internal outbox table. The database API can insert an event within the same
business transaction. The CLI worker is explicitly invoked, drains currently
due mapped events, and exits when none are waiting. Delivery is at least once;
handlers must be idempotent by event ID.

This is not a general queue platform: the web server starts no worker, Zelyra
source has no handler declaration, and there is no scheduler, distributed queue
management, or exactly-once delivery. See the [outbox guide](../outbox.en.md).

## Language compatibility line 0.1

The corpus adds valid lexer, parser, and Option typing fixtures plus a stable
diagnostic for an invalid lexer token. Accepted sources are formatted twice to
check formatter idempotence. This expands the corpus; it is not a complete 1.0
conformance claim.

The bilingual [readable regex text-edit design](../design/readable-regex-text-editing.en.md)
is included. The executable CLI command is planned for 0.9.0.

## Database and runtime limits

This release does not add full PostgreSQL parity. Supported commands and
runtime paths are listed in the [database compatibility matrix](../database-compatibility.en.md).
MySQL remains limited to its documented typed, parameterized query path.
