# Zelyra 1.2.23

Zelyra can now validate writes to tenant-scoped tables in authenticated API
routes without trusting a tenant identifier supplied by the client.

For `api ... validates invoices`, the route must declare `requires auth`; the
project's `auth` declaration must configure a membership table. The request
must not declare the scoped tenant column as an input. Zelyra resolves the
selected tenant against the signed-in session and active memberships, supplies
that verified value to table-invariant evaluation, and passes it to the handler
as the final parameter with the table column's declared name and type. Missing,
conflicting, forged, or unauthorized tenant context is rejected before the
handler. A request body containing the tenant key is rejected.

This change validates the declared request values and the verified tenant
context before a handler runs. It does not generate database writes, constrain
arbitrary handler transformations, or validate direct SQL writes. Use database
constraints for invariants that every writer must preserve.

A compiler-checked sample is available at
[`examples/tenant_api_validation.zyl`](../../examples/tenant_api_validation.zyl).
