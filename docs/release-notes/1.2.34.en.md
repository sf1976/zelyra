# Zelyra 1.2.34

Zelyra 1.2.34 improves bounded process integration and the Laravel importer's
static migration analysis. It does not claim a complete Laravel website
migration.

## Changes

- Preserve Laravel `mediumText` and `longText` capacities in selected
  generated MariaDB schemas through the compiler-checked
  `text_storage medium|long` column modifier. MariaDB emits `MEDIUMTEXT` or
  `LONGTEXT` and rejects unsupported indexes on these unbounded columns.
  PostgreSQL and SQLite use native `TEXT`; the importer reports their
  backend-specific size limits. This preserves supported schema capacity but
  does not migrate Laravel website behavior.
- Add `run_process_piped` behind the declared `Process` capability and
  configured executable allowlist. Input size, output size, and timeout remain
  bounded. The operation is available consistently across supported AST, MIR,
  and bytecode execution paths; it is not an OS sandbox for arbitrary source
  code.
- Correct ordered Laravel migration analysis for a narrow guarded case. A
  complete supported `Schema::table` callback is skipped only when its body is
  one `if (!Schema::hasColumn(table, column))` guard and an earlier migration
  declares that exact column. Mixed and unsupported callbacks remain
  conservative.
- Against `/opt/siedelmann-laravel/app`, the generated `quotes` schema no
  longer rejects the later migration callback: `signature_data` remains from
  the earlier migration, while `signed_at` and `signed_by_name` are correctly
  omitted because Laravel skips that callback. The analysis did not execute
  PHP, read `.env`, query the database, or modify the Laravel project.

## Verification and limits

The three focused migration tests, workspace formatting/check/tests/Clippy,
handbook validation, and the source-only importer acceptance check passed.
GitHub CI passed Linux and Windows release builds, the full workspace and
Docker/browser integration suite, MariaDB 10.11/11.4/11.8/12.3, MySQL 8.4,
fuzzing, dependency audit, and editor verification.

This release improves one static schema-analysis case. The acceptance project
still reports 2,268 importer findings; most routes, controller workflows, and
Blade behavior are not migrated. Database-only workspace tests requiring an
external disposable database remain separately identified by the test suite.
