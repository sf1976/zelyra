# Zelyra 1.2.16

Zelyra 1.2.16 adds checked supplemental content inside individual TableView
cells without bypassing generated search, sorting, filters, pagination, or
security.

## Supplemental row fields

`view.row_fields` selects SQL result fields that row templates can use for
cell content and actions without giving each field a separate table column:

```zelyra
database main { engine: mariadb }
table items {
    id: Id primary auto
    sku: String required
    customer_number: String required
}
struct ItemRow { id: Id sku: String customer_number: String }

tableview Items {
    source sql<ItemRow[]> {
        SELECT id, sku, customer_number FROM items
    }
    columns { sku }
    view {
        row_fields { id customer_number }
        column_content {
            item: item
            sku {
                html { <small>Customer number: {item.customer_number}</small> }
            }
        }
        row_actions {
            item: item
            html { <a href="/items/{item.id}">Open item</a> }
        }
    }
}

fn main() {}
```

The SQL projection must return every displayed field and every explicitly
selected supplemental field. Zelyra checks field names, target columns, and
template bindings against the result type. Undeclared fields cannot be read.
Values are escaped during HTML rendering. Supplemental content cannot contain
forms.

Supplemental fields are presentation-only context. They do not automatically
become searchable, filterable, or sortable; those operations remain governed
by the explicit TableView declarations.

## Compatibility and limits

Existing TableViews without `row_fields` or `column_content` keep their
previous behavior. `columns` continues to define visible columns. This
extension adds neither a write action nor arbitrary dynamic SQL. Arbitrary CSS
classes and HTML styling are not generally statically checked.

A complete example is available at
[`examples/generated_page_customization/main.zyl`](../../examples/generated_page_customization/main.zyl).

## Invoice tutorial

The landing page and component gallery read their labels from `locales/de.json` or `locales/en.json`,
selected by `ZELYRA_LANGUAGE` in `.env`. The shared header now includes a
visible switch for system, light, and dark themes. The choice is stored in the
browser; browser checks cover both themes and the component gallery's
accessibility.
