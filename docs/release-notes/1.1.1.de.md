# Zelyra 1.1.1

Zelyra 1.1.1 korrigiert irreführende Studio-Meldungen beim Öffnen und Starten
lokaler Webprojekte.

- Wenn ein Browser eine lokale Studio-Anfrage schließt, wird der normale
  `Broken pipe`-Abbruch nicht mehr als lauter Fehler protokolliert.
- Die erfolgreiche Meldung `Zelyra server listening` geht auf die
  Standardausgabe und erscheint in den Studio-Logs als Information unter
  `preview.stdout`.
- Ist der angeforderte Port belegt, bindet `zelyra serve` einen freien lokalen
  Port und gibt die tatsächliche Adresse aus. `zelyra doctor` meldet den
  belegten Port als Warnung, wenn dieser Ausweichweg verfügbar ist.
- Canvas erklärt jetzt klar, dass es nur eine statische Prüfvorschau rendert.
  Zum Ausführen von Routen und Handlern in Studio **Starten** und anschließend
  **Anwendung im Browser öffnen** wählen. Die Canvas-Sandbox bleibt aktiv.
- Das Docker-Compose-Port-Fallback bleibt verfügbar: Ist der Web- oder
  MariaDB-Hostport eines erzeugten Projekts belegt, versucht das Setup einen
  freien Port und aktualisiert die lokale Projektkonfiguration.
- Kann die Outbox MariaDB nicht erreichen oder fehlt ihre Tabelle, nennt Studio
  beide möglichen Ursachen und den Setup-Befehl. Bei Projekten ohne Outbox-
  Nutzung kann die Meldung geschlossen werden.

Dieses Patchrelease ändert weder die Sprachkompatibilitätslinie noch benötigt
es für veröffentlichte Zelyra-Anwendungen Node.js, npm oder eine zusätzliche
Browser-Runtime.
