# Zelyra 1.2.13

Create new applications in an explicit project layout with
`zelyra new --layout standard`. The scaffold contains `routes/`, `domain/`,
`schema/`, `public/`, and `assets/`. Existing projects keep their previous
behavior unless they opt into the profile. `check`, `run`, and `serve` validate
required directories and reject missing roots, symlinks, and paths outside the
project with `E-LAYOUT-001` and `E-LAYOUT-002`.

Within the standard layout, imports such as
`import "domain::sales::actions" as sales` resolve to
`domain/sales/actions.zyl`. This reuses existing import syntax; `pkg:` and
relative package imports remain available. Schema, domain, and route modules
are the permitted namespace roots. Path resolution blocks traversal and
symlink escapes.

This is the first secure layout foundation. Full architecture rules,
`zelyra migrate-layout --check`, database templates, and a `plugins/` loader
are not part of this release. `strict_architecture = true` is rejected as
unsupported; the setting does not claim checks that do not run.
