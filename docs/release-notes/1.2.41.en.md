# Zelyra 1.2.41

This release adds one deliberately narrow Laravel website-import mapping:
`Route::get('/favicon.ico', function () { return
response()->file(public_path('favicon.ico')); });` is imported as a same-origin
static asset route.

The importer accepts only an ungrouped, middleware-free `GET` closure with one
literal `public_path(...)` file return. The route URL must exactly match the
file path below Laravel's `public/` directory. The regular file is copied using
the existing bounded, symlink-safe asset pipeline. The generated project
records the mapping in `STATIC_ASSET_ROUTES.json` and serves it through
Zelyra's existing public-file server.

This is not general Laravel route support. Dynamic responses, middleware,
groups, controller handlers, and PHP execution are not translated. The real
project check against `/opt/siedelmann-laravel/app` is read-only: it does not
run PHP, read `.env`, or inspect source application rows. It verifies that the
generated `/favicon.ico` is byte-identical to the source and that the generated
scaffold passes `zelyra check`.

- Full GitHub PR CI passed on the merged source tree, including workspace and
  end-to-end tests, MariaDB 10.11/11.4/11.8/12.3 compatibility, MySQL 8.4,
  dependency audit, bounded fuzzing, and Windows updater checks.
- Linux and Windows release archives and SPDX SBOMs were built and verified in
  the PR release workflow. The final versioned release workflow verifies the
  release-tagged artifacts again.
- The real-project acceptance check accounted for 576 PHP files and 2,274
  importer findings, compiler-checked the generated scaffold, and verified the
  byte-identical favicon mapping. It did not claim complete website migration.

## Installation

Download the Linux `.tar.gz` or Windows `.zip` archive from the GitHub release
and verify its adjacent `.sha256` file before extracting it.
