# Zelyra 1.2.12

Applications with typed package settings can now manage them through the
authenticated `/__zelyra/module-settings` page. The route is generated only
when configured. Writes require the configured permission and CSRF protection,
use the same schema validation as the package API, and are revision-checked.
Secret values are never returned; accepted values may reference only
environment variables already available to the server process. Changes take
effect after a restart.

The standard Zelyra UI `Dialog` no longer requires an explicit ID or
`close_label` for the common case. IDs are stable and unique within a rendered
document, and close labels use UI localization. The native modal supports
keyboard interaction, focus handling, and responsive content.

The invoice tutorial now aligns custom AppShells with generated CRUD forms.
`zelyra.theme.css` is directly available in the Studio file explorer, with
documented starter content for projects that do not yet have the file. Studio
browser coverage now waits for the actual compiler response to unsaved edits.

The settings page requires an auth configuration with `admin_permission` and a
configured package declaring settings. Changes require a restart. The
reverse-proxy Host allowlist is validated; a loopback Nginx test covers static
files and proxy routing. Apache and TLS integration were not tested in this
release. MIR/Bytecode web parity and the remaining ecosystem gates stay open
and are assigned to subsequent releases through 1.3.0.
