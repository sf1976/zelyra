# Zelyra 1.2.30 — tenant-safe schema references and Laravel import coverage

Zelyra 1.2.30 adds explicit foreign-key targets for scalar ID columns using
`references <table>`. The column keeps its nominal Zelyra ID type while the
schema planner emits a database foreign key. References between tenant-scoped
tables use composite tenant keys, preserving tenant identity and allowing the
database to reject cross-tenant references. The schema plan adds a unique
`(tenant_id, id)` target key when needed and avoids collisions with existing
constraint names. MariaDB, PostgreSQL, and SQLite DDL planning is covered.

The Laravel website importer now reports coverage for every scanned PHP file,
checks its generated project and offline package closure, and has stronger
tenant-aware schema mapping. Checked standalone forms can validate captured
route tokens with a read-only SQL gate before rendering and require the same
record match before a CSRF-protected write. An end-to-end example verifies
invalid tokens, successful unsubscribe, and idempotent repeat submission.

These features do **not** constitute a complete Laravel website migration.
The source-only check against `/opt/siedelmann-laravel/app` inventoried 572 PHP
files and 2,263 findings: 1,387 manual/unresolved and 876 partial. Its generated
scaffold passed `zelyra check`, but no Laravel PHP was executed and no project
source or application database rows were changed. Tenant-owned public token
routes that cannot prove an authorized tenant context remain manual findings;
the real unsubscribe workflow is not emitted. Controllers, Blade behavior,
uploads, custom tenant selection, registration, two-factor authentication,
and other application workflows are not automatically migrated.

Generated invoice numbers now scope collision lookups and the subsequent
update to the active tenant when the CRUD resource is tenant-scoped. Locale
markers in generated `has_many` legends also survive HTML escaping and are
localized before the response is sent. The existing numbering logic remains
limited to `invoice_number` and still derives identifiers from database IDs;
configurable number-series formats and per-tenant counters are not
implemented.

The locked `rustls-webpki` and `webpki-roots` TLS dependencies were updated to
patch releases containing the certificate fixes identified by release CI.

## Limits

Importer findings are analysis classifications, not migrated-feature counts.
The local project check is source-only and does not execute generated HTTP
workflows. Separate fixture and database tests cover only the explicitly
listed paths. Laravel `SET NULL` behavior cannot be preserved for a required
composite tenant foreign key; the importer records the difference and emits
`RESTRICT` for review. Generated schema is a candidate and is never applied to
the source database.
