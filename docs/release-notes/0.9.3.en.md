# Zelyra 0.9.3

**Status:** Experimental compiler release; not approved for production use.
Independent human acceptance is reserved for 1.0.0.

## What changed

- Studio now has a session-protected, read-only database row browser with
  bounded pages. It can preview, compiler-check, and explicitly apply simple
  source-column additions and edits. These source changes do not apply a live
  database migration.
- Studio can create a declared MariaDB database after confirmation when the
  project already has a configured connection. Database creation does not
  apply tables. Connection selection and PostgreSQL/MySQL database creation
  are not implemented; MySQL schema introspection is unsupported.
- `zelyra migrate laravel <project> --report <path>` creates a read-only
  Markdown or JSON inventory with source locations, explicit unresolved
  findings, and safe next steps. It does not execute PHP or Artisan, read
  `.env`, connect to a database, or alter the Laravel project. It is a
  pattern-based first inventory, not a PHP parser, full project graph, or
  automatic migration.
- The language adds native Decimal, Date, Time, Duration, Bytes, Tuple, and Set
  values, with `List<T>` as an alias for arrays. CSV and labyrinth examples
  exercise these capabilities and expected errors.
- Tutorial/Studio startup defects are fixed; CLI help now has detailed nested
  command help, including route inventory and database commands.

## Type coverage

The `examples/type_system` CLI integration test passes its positive and
expected-failure cases. Its report currently lists **17 supported, 5 partial,
and 3 unavailable entries**. This is not complete coverage of every requested
type concept: user-defined enums, function values, and user-defined generics
remain unavailable; records use value semantics rather than observable class
identity. The 0.9.9 feature-freeze gate requires a fresh run after the planned
language work and explicit accounting for every remaining item.
