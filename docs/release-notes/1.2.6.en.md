# Zelyra 1.2.6

Zelyra 1.2.6 makes registry package mutations recoverable after process
interruption. It adds a per-project lock for package mutations, a versioned
transaction journal, and the `zelyra package recover` command.

## Recover package transactions

`zelyra package recover` previews the proposed recovery by default. A
transaction is changed only when you run `zelyra package recover --apply`.
Prepared transactions restore the backed-up manifest and lockfile and clean up
cache paths created during the operation. Already committed transactions are
safely cleaned up.

Package installation, updates, removal, cache cleanup, and trust changes use
the same per-project operation lock. New package mutations are rejected while
a recovery journal is pending. Interrupted cache cleanup uses validated
quarantine directories and never overwrites an existing package.

Recovery protects against inconsistent package changes after interruption. It
is not an atomic transaction across all files on the filesystem. Malformed
journals, symlinks, path conflicts, and I/O failures fail closed while
preserving available recovery data.

## Next steps

Transitive registry dependencies, typed tenant/query/request/form pipelines,
and persistent transactional scheduler jobs are not part of 1.2.6. They remain
assigned to dedicated releases in the roadmap through 1.3.0.
