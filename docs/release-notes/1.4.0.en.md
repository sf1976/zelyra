# Zelyra 1.4.0 — Production Core & Developer Joy

## First-Class Test Runner (`zelyra test`) & Declarative `test` Blocks

Zelyra `1.4.0` introduces declarative `test` blocks and a built-in `zelyra test` CLI runner:

```zyl
fn divide(a: Int, b: Int) -> Result<Int, String> {
    if b == 0 {
        return Err("division by zero")
    }
    return Ok(a / b)
}

test "computes quotients and rejects division by zero" {
    quotient = assert_ok(divide(20, 4))
    assert_eq(quotient, 5)
    assert_ne(quotient, 0)
    message = assert_err(divide(20, 0))
    assert_eq(message, "division by zero")
}
```

- **Standalone test files:** Files containing `test "..."` declarations do not require `fn main()`. `zelyra test [path]` automatically discovers `tests/*.zyl`, `tests.zyl`, or `main.zyl`.
- **Full compiler discipline:** Test blocks pass through the same static type, SQL, form, API, and capability checks as production code. A test without `uses FileSystem` or `uses Database` cannot silently perform those effects.
- **Automatic database rollback sandbox:** Tests declaring `uses Database` automatically execute inside `with_rollback_transaction` on MariaDB/MySQL and PostgreSQL so test mutations are never persisted.
- **CI- & AI-ready output:** `--filter <substring>` targets specific tests; `--format json` emits deterministic JSON (`schema_version: "1"`) with timings, captured output, status, and exact source locations.

## Rich Assertions Across AST, MIR & Bytecode v30

Four new assertion builtins run with full parity across the type checker, AST runtime, HIR/MIR, and Bytecode v30 VM:

- `assert_eq(left, right[, message]) -> Unit`
- `assert_ne(left, right[, message]) -> Unit`
- `assert_ok(result[, message]) -> T` (returns the unwrapped `Ok` value)
- `assert_err(result[, message]) -> E` (returns the unwrapped `Err` value)

## Upgraded Zelyra Language Server (`zelyra lsp`)

- **`textDocument/formatting`:** Formats Zelyra buffers directly in the editor via the deterministic Zelyra formatter (`documentFormattingProvider: true`). Syntactically invalid buffers return empty edits without corrupting code.
- **Enriched `textDocument/hover`:** Surfaces declared table `states` transitions (including `[guarded]` markers) and function `uses` capabilities as well as `requires`/`ensures` contract counts.
- **Outline & Completion:** `test "..."` blocks appear in `textDocument/documentSymbol`; `textDocument/completion` includes `assert_eq`, `assert_ne`, `assert_ok`, `assert_err`, `test`, `states`, and `when`.

## Honest Scope Notes

- Native pooled MariaDB/MySQL and PostgreSQL drivers, string interpolation (`"Total: {total}"`), and generic functions (`fn identity<T>(value: T) -> T`) were already present in the core and now integrate seamlessly with `zelyra test` and the rollback transaction sandbox.
- Contract/property fuzzing and the full Mini-ERP Benchmark 01 remain ongoing hardening items and are not claimed as completed in `1.4.0`.
- AST remains the default execution path; MIR and Bytecode v30 remain opt-in.
