# Zelyra 1.6.0 — Financial & Temporal Integrity (`Money<C>`, `ledger`, `auditable` & EN 16931)

## Währungssicheres `Money<Currency>`

Geldbeträge tragen ihre Währung direkt im Typ – Mischen unterschiedlicher Währungen ist ab `1.6.0` ein harter Compile-Zeit-Fehler:

```zyl
net = money<EUR>("100.00")
tax = money<EUR>("19.00")
gross = net + tax                              // Money<EUR>
usd = convert_money<EUR, USD>(gross, decimal("1.10"))  // explizite Half-Even-Umrechnung
// net + usd -> Compile-Fehler: cannot mix currencies `Money<EUR>` and `Money<USD>`
```

- Unterstützt ISO-4217-Währungs-Tags (`EUR`, `USD`, `CHF`, `GBP`, `JPY`, `CAD`, `AUD`, `SEK`, `NOK`, `DKK`, `PLN`, `CZK`) sowie benutzerdefinierte Währungstypen.
- Exakte `Decimal`-Arithmetik ohne Gleitkomma-Rundungsfehler (maximal 4 Nachkommastellen bei `money<C>`).

## Unveränderliches `ledger` (`E-LEDGER-001`) & bitemporale `auditable`-Tabellen

```zyl
ledger journal_entries {
    id: Id primary auto
    journal_id: Id required
    account: String(64) required
    debit: Decimal(12, 2) required
    credit: Decimal(12, 2) required
}

table contracts auditable {
    id: Id primary auto
    title: String(120) required
}
```

- **Compile-Zeit-Unveränderlichkeit (`E-LEDGER-001`):** Jedes SQL-`UPDATE` oder `-DELETE` auf einer `ledger`-Tabelle (in Funktionen, Tests, Workflows, Formularen oder CRUD-Aktionen) wird vom Compiler kategorisch abgewiesen.
- **Nullsummen-Prüfung:** `verify_ledger_balance(debits, credits)` prüft `sum(debit) == sum(credit)` mit exakter Dezimalarithmetik über AST, MIR und Bytecode v30.
- **Bitemporale Metadaten:** `table <name> auditable` ergänzt automatisch `valid_from`, `valid_to`, `recorded_at` und `recorded_by` im erzeugten Schema; `zelyra reflect --format=json` exportiert `is_ledger` und `is_auditable`.

## Typisierte EN-16931-E-Rechnungen (`einvoice_xml` & `einvoice_validate`)

- `einvoice_xml(invoice_number, issue_date, currency, seller_name, buyer_name, net_total, tax_total, gross_total)` erzeugt escaped EN-16931-`CrossIndustryInvoice`-XML (`urn:cen.eu:en16931:2017`) und erzwingt `net_total + tax_total == gross_total`, ISO-Datum und 3-stelligen ISO-Währungscode.
- `einvoice_validate(xml)` prüft Struktur, EN-16931-Profil, Summen-Konsistenz und weist `<!DOCTYPE`/`<!ENTITY` zum XXE-Schutz ab.

## Ehrliche Einordnung

- Transaktionale `post_ledger { ... }`-Blöcke mit Hash-Kette, `zelyra ledger verify`, `AS OF`-Zeitreise-SQL-Syntax und PDF/A-3-Einbettung in die Mail-Outbox bauen auf diesem 1.6.0-Kern auf und werden nicht als bereits vollständig umgesetzt beansprucht.
- AST bleibt Standard; MIR und Bytecode v30 bleiben opt-in.
