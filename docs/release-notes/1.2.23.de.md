# Zelyra 1.2.23

Zelyra kann Schreibanfragen in authentifizierten API-Routen nun auch für
mandantengebundene Tabellen prüfen, ohne einem vom Client gelieferten
Mandantenbezeichner zu vertrauen.

Für `api ... validates invoices` muss die Route `requires auth` deklarieren;
der Projekt-`auth`-Block benötigt eine Mitgliedschaftstabelle. Die
Mandantenspalte darf nicht als API-Eingabe deklariert werden. Zelyra prüft die
ausgewählte Mandanten-ID anhand der angemeldeten Sitzung und aktiver
Mitgliedschaften, übergibt den verifizierten Wert an die Tabelleninvarianten
und als letzten Handlerparameter mit Name und Typ der Tabellenspalte. Fehlender,
widersprüchlicher, gefälschter oder nicht autorisierter Kontext wird vor dem
Handler abgewiesen. Ein Mandantenschlüssel im Request-Body wird zurückgewiesen.

Die Funktion prüft deklarierte Request-Werte und den verifizierten
Mandantenkontext vor dem Handler. Sie erzeugt keine Datenbankschreibvorgänge,
begrenzt keine beliebigen Handler-Transformationen und prüft keine direkten
SQL-Schreibzugriffe. Invarianten, die jeder Schreiber einhalten muss, benötigen
Datenbank-Constraints.

Ein compilergeprüftes Beispiel steht unter
[`examples/tenant_api_validation.zyl`](../../examples/tenant_api_validation.zyl).
