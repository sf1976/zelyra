# Zelyra 0.7.0

Zelyra 0.7.0 adds Zelyra Studio, a guided invoice tutorial, a bounded MySQL
runtime, and the first experimental tenant-aware CRUD path. This release remains
experimental and is not approved for production use. Human acceptance is
reserved for 1.0.0.

## Zelyra Studio

`zelyra editor [directory] [--port <port>]` starts a local browser editor on
`127.0.0.1`. Studio includes a project tree, tabs, syntax highlighting,
search/replace, Zelyra keyword completion, conflict-checked saves, new files,
compiler diagnostics, and explicit formatting. Files are limited to 1 MiB.
Hidden files, secrets, generated directories, and symbolic links are excluded.
Writes require a random session token and the same browser origin. The editor
runs no shell commands and sends no source code to external services.

Studio is a local development tool, not a complete IDE. A visual database
browser and CRUD builder are outside this release.

## Guided invoice tutorial

`zelyra --tutorial invoice` guides users through short, repeatable terminal
steps for customer entry, item entry, a dashboard, and invoice creation. Each
generated stage can be checked; the tutorial does not replace production
verification or operator configuration.

## Bounded MySQL runtime

The verified MySQL scope covers parameterized, typed SQL queries against MySQL
Server 8.4.11. Schema and administration commands fail closed with `E-DB-019`.
Migrations, generated CRUD/web routes, and authentication through MySQL are not
included. This does not establish general MySQL compatibility.

## Experimental tenant CRUD path

On MariaDB, one generated CRUD route family can use an explicitly
tenant-scoped table. The runtime binds identity to a validated database
session, checks memberships per request, treats header and URL values only as
selectors, and scopes generated reads and writes to the selected tenant. The
implementation is deliberately limited to one table.

This is not full multi-tenancy. Tenant-aware migrations or backfills,
relationships, custom SQL actions, TableViews, exports, and PostgreSQL/MySQL
tenant runtimes are not supported. Existing records are not automatically
assigned to a tenant. Use tenant data only with an explicitly reviewed schema
and ownership mapping.

## Setup and tests

`zelyra setup` diagnoses a likely mistyped absolute path such as `/project`
when `./project` exists. For a minimal `zelyra init` project, the error explains
that database setup requires a MariaDB project.

Language compatibility line `0.1` remains independent of the compiler version.
An initial runnable corpus checks accepted and rejected programs, diagnostic
codes, runtime output, and formatting. It is not a complete 1.0.0 conformance
claim.

## Maturity and limits

0.7.0 is experimental and is not approved for production use. It does not claim
full PostgreSQL parity, universal SQL, full multi-tenancy, a complete IDE,
or general formal verification. Independent human acceptance is reserved for
the immutable 1.0.0 candidate.

Verification evidence and remaining technical limits are recorded in the
[0.7.0 release plan](../release-plans/0.7.0.en.md) and the
[tenant threat model](../release-readiness/0.7.0-tenant-threat-model.en.md).
