# Zelyra 1.2.5

Zelyra 1.2.5 adds fixed-port Linux services, a scheduler that runs inside the
active project service, and a signed package-registry workflow that remains
usable offline after installation.

- `zelyra service install --port <port>` installs a Linux systemd user service
  for the current project. `status`, `restart`, `change --port`, and `remove`
  manage it. Ports are never selected automatically; a busy port is an error.
  Port changes check listener readiness and restore the previous unit and
  service if restarting the new configuration fails.
- `restart` waits for the HTTP listener on the configured port. A successful
  return therefore means that the service is locally reachable. User services
  start after reboot and before login only when systemd lingering is enabled
  for the account.
- The resident scheduler runs only inside the installed, active Zelyra project
  service. It reloads schedule declarations from current source at each minute
  boundary. It does not install host cron entries; `zelyra schedule status`
  reports whether a schedule is actually active. Setup idempotently initializes
  MariaDB outbox tables for scheduled mail handlers.
- `zelyra new` creates `public/`. `zelyra serve` delivers bounded static files
  from it with MIME types and GET/HEAD support. Declared routes take precedence;
  traversal, dotfiles, and symlinks outside the document root are blocked.
  Examples explain deployment behind Apache and Nginx.
- The registry supports Ed25519-signed source packages, explicit publisher
  trust, exact-version selection, digest and compatibility checks, and
  provenance in `zelyra.lock`. Registry access is explicit; installed projects
  can be checked and run offline. Docker bundles relocate package sources into
  portable project paths.
- Studio Run supports interactive `read_console` input. Schedule status and
  runtime budgets are documented. Mutable array-index assignments in MIR and
  Bytecode avoid unnecessary copies; AST remains the reference and default
  backend.

## Limits

This release does not add a general transactional job queue, distributed
scheduler leases, or automatic retry/catch-up execution. Tenant-query HIR and
the full typed request/form lifecycle remain follow-up work for 1.2.6. Recovery
after process interruption and resolution of separately published transitive
packages are also assigned to 1.2.6. Apache/Nginx configuration is documented
as examples; it was not installed on a production web server.

The supported MIR and Bytecode subsets remain experimental. AST is still the
default; this release does not claim full backend parity or general performance
improvements.
