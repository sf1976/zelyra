# Zelyra 1.2.8

Zelyra 1.2.8 adds a checked SQL query plan to HIR and MIR and tightens
validation of form-action redirects.

## Typed SQL metadata

Each `sql<T> { ... }` expression keeps its existing syntax. HIR now records its
SQL operation, deterministically ordered table accesses, bound local IDs, and
inferred parameter types when supplied by the successful type-check pass. MIR
carries this plan, and its verifier recomputes the operation, table accesses,
and bindings from the SQL source. A stale plan is rejected with
`E-MIR-VERIFY-004`.

This metadata does not authorize database access or introduce a second query
language. Schema, capability, actual parameter-type, and tenant-scope checks
remain authoritative. Raw SQL against tenant-scoped tables continues to fail
closed; authenticated generated CRUD is the supported tenant-scoped read/write
path. Bytecode continues to validate SQL against the checked schema before
database host calls.

## Form redirects

Form-action `redirect` values must be local absolute paths such as
`/customers`. External URLs, protocol-relative paths, backslashes, and control
characters are rejected by `zelyra check` with `E-FORM-007`. Local query strings
remain accepted. Structured `check --format json` output preserves the stable
diagnostic code.

## Verification and limits

The release passed the workspace, database compatibility, Docker, invoice
tutorial, package, and release-artifact checks in CI. The detailed per-check
results and any database-only ignored cases are recorded by the release
workflow and in the 1.2.8 release plan.

The HTTP server continues to use the AST execution path. MIR and bytecode remain
opt-in experimental execution backends; this release does not claim full
cross-backend request or web-runtime parity.
