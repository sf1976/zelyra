# Zelyra 0.5.0

**Status:** stable experimental release · **Release:** `v0.5.0` ·
**Verified candidate:** `v0.5.0-rc.1` · **Human acceptance:** deferred to 1.0.0 by explicit project-owner decision.

This release carries the changes and limits below. It is experimental and does
not claim production approval or complete deployment closure. No independent
human study was conducted for 0.5.0; do not use it as evidence of human
acceptance or production readiness.

## Included

- Experimental Docker bundles for the statically recognized subset of a
  multi-file project. The manifest keeps `source_closure_complete` and
  `complete_deployment` false. Operators must inspect unresolved references,
  effects, and runtime requirements before use.
- Separate Docker apps for invoice and inventory CRUD with independent
  `DATABASE_URL`, separately provisioned MariaDB schemas, and least-privilege
  database accounts.
- Modular customer/order web workflow with authentication, viewer permissions,
  relationship validation, reporting, and stale/concurrent form conflict
  detection.
- Disposable MariaDB rehearsals for backup/restore, additive schema changes,
  DDL/journal crash recovery, and rollback of an uncommitted customer update
  after server restart.

## Explicit limits

Complete dependency/effect closure, shared schema ownership, a reusable
multi-connection database module, a general inventory product, public API and
browser parity, and application-wide audit/concurrency guarantees are outside
this candidate's scope. Bundle generation does not certify a production
deployment. Building the Docker apps fetches the pinned public compiler commit
and Rust dependencies from GitHub and the crate registry.

## Acceptance and upgrade

Independent human onboarding acceptance is deferred to the first major release,
1.0.0, by explicit project-owner decision. The [0.5.0 decision record](../release-readiness/0.5.0-human-acceptance.en.md)
documents the deferral and is not test evidence. The technical release gates
and exact-candidate artifact checks passed. Before database
changes, inspect `zelyra db plan --format=json` and verify an independent backup.
Read the [candidate verification record](../release-readiness/0.5.0-candidate-verification.md)
for exact commit and artifact evidence. Human acceptance remains a required
gate before the productive 1.0.0 release.
