# Zelyra 1.2.16

Zelyra 1.2.16 erweitert TableView-Zeilen um geprüfte Zusatzinformationen in
einzelnen Tabellenzellen, ohne die generierte Suche, Sortierung, Filterung,
Pagination oder Sicherheit zu umgehen.

## Zusatzfelder für Zeilenvorlagen

`view.row_fields` wählt SQL-Ergebnisfelder aus, die in Tabellenzeilen für
Zusatzinhalte und Aktionen verfügbar sind, aber keine eigenen Tabellenspalten
erhalten:

```zelyra
database main { engine: mariadb }
table items {
    id: Id primary auto
    sku: String required
    customer_number: String required
}
struct ItemRow { id: Id sku: String customer_number: String }

tableview Items {
    source sql<ItemRow[]> {
        SELECT id, sku, customer_number FROM items
    }
    columns { sku }
    view {
        row_fields { id customer_number }
        column_content {
            item: item
            sku {
                html { <small>Kundennummer: {item.customer_number}</small> }
            }
        }
        row_actions {
            item: item
            html { <a href="/items/{item.id}">Artikel öffnen</a> }
        }
    }
}

fn main() {}
```

Die SQL-Projektion muss alle angezeigten und ausdrücklich ausgewählten Felder
enthalten. Zelyra prüft Felder, Spaltenziele und Vorlagenbindung gegen den
Ergebnistyp. Nicht deklarierte Felder sind nicht zugänglich. Die Werte werden
beim HTML-Rendering escaped. Zusätzliche Inhalte dürfen keine Formulare
enthalten.

Zusatzfelder sind nur Darstellungskontext. Sie werden nicht automatisch für
Suche, Filter oder Sortierung freigegeben. Dafür gelten weiterhin die
expliziten TableView-Deklarationen.

## Kompatibilität und Grenzen

Bestehende TableViews ohne `row_fields` oder `column_content` behalten ihr
bisheriges Verhalten. `columns` definiert weiterhin die sichtbaren Spalten.
Diese Erweiterung führt weder eine Schreibaktion noch freie dynamische SQL-
Abfragen ein. Beliebige CSS-Klassen und HTML-Stile werden nicht allgemein
statisch geprüft.
