# Zelyra 0.9.4

Zelyra 0.9.4 improves command-line setup and the invoice tutorial's Studio
workflow. This is an experimental release and is not approved for production.

## Changes

- Docker Compose build and startup output is visible while
  `zelyra setup <directory> --all` runs. Schema setup reports progress, includes
  its final error, and prints the application address.
- `zelyra db create` help now says that it prints checked table-creation SQL.
  It does not create a database. Use `zelyra db setup` for a MariaDB database
  and schema, or `zelyra setup <directory> --all` for a local Docker project.
- The main help includes outbox and database history commands. Detailed help
  covers the text-edit workflow and the database backend limits.
- The invoice tutorial creates a private `.env` with both named and fallback
  database URLs even with `--no-start`. The E2E workflow now creates a customer,
  follows the save redirect, and verifies the customer list through the same
  local web preview used by Studio.
- CRUD query failures now advise checking database availability and applying
  the project schema without displaying sensitive driver details.
- Unqualified MariaDB `DECIMAL` columns no longer appear to have destructive
  type drift on a repeated setup; the tutorial integration test applies its
  schema twice and checks the second run is clean.
- Setup now stops immediately on non-retryable schema errors. Changes requiring
  explicit approval are refused with `db plan` and `db apply --allow-risky`
  instructions; only transient database startup errors are retried.
- `zelyra update --check` explains how to recover from GitHub HTTP 403/429 rate
  limits instead of returning an unhelpful download error.

Independent human acceptance remains reserved for 1.0.0. The type-system,
relational IDE, Laravel migration, chart, and presentation work continues in the
staged 0.9.5–0.9.8 roadmap.
