# Zelyra 1.0.7

**Release:** `v1.0.7` · **Sprachkompatibilität:** `0.1`

Zelyra 1.0.7 erweitert Sprache und Runtime für gut prüfbare Businesslogik und
ergänzt eine lokale, serverseitige Text-PDF-Pipeline für Views und
transaktionale E-Mail-Anhänge.

## Sprache und Compiler

- `if` kann einen typisierten Wert liefern. Records lassen sich mit
  `Customer { ..old, active: true }` kopieren und gezielt aktualisieren.
- Lexikalische Lambdas können mit `map`, `filter`, `find` und `reduce` verwendet
  werden; Callback-Eingabe und Ergebnis werden statisch geprüft.
- `match` unterstützt verschachtelte Record-Muster und boolesche Guards.
  Guards allein gelten nicht als Beweis für vollständige Fallabdeckung.
- Kontextuelle Feldnamen wie `version` und `type` sind in Records zulässig.
  Tupel können reguläre Rückgabewerte sein und außerhalb von Schleifen
  destrukturiert werden.
- `[runtime] max_stack_depth` erlaubt Werte von 1 bis 500; der Standard bleibt
  20. `zelyra run datei.zyl --max-steps N` begrenzt Anweisungen und
  Ausdrucksauswertungen über alle `parallel`-Zweige hinweg und meldet
  Überschreitungen als `E-RUNTIME-001` an der Quellstelle.
- `type OrderId = Id` bleibt nominal und nimmt kein gewöhnliches `Int`-Literal
  an. Fachliche Zahl-Aliase verwenden `type OrderNumber = Int`.
- API-Fehler-Payloads verlangen `output Result<T, E>` mit passendem `E`.
  Transaktionen lassen sich offline prüfen, benötigen beim Ausführen aber eine
  aktive Datenbanklaufzeit.
- Ein `auth`-Block registriert vorhandene Login-, Logout-, Sitzungs-, Reset-,
  MFA- und konfigurierbare Admin-Handler. `zelyra routes` zeigt tatsächlich
  verfügbare HTTP-Methoden und Pfade; optionale Tabellen und Einstellungen
  bestimmen optionale Routen. CRUD-Berechtigungen werden serverseitig geprüft.
- Nicht bereitgestellte benannte View-Slots rendern ihren Fallback.
  `parallel` wartet am Blockende auf seine `await`-Bindings und macht die
  geprüften Werte im umschließenden Scope verfügbar.

## Serverseitiges PDF und E-Mail-Anhänge

`render_pdf("InvoicePrint", invoice)` rendert eine deklarierte View lokal in
`Bytes`. Record-Platzhalter werden escaped; `for item in collection` wertet
Record-Arrays aus. `mail_queue` kann innerhalb derselben Datenbanktransaktion
einen PDF-Anhang in der MariaDB-Outbox speichern.

Der Renderer liefert ein paginiertes, durchsuchbares Text-PDF. HTML und
expandierte Ausgabe sind auf jeweils 2 MiB, Collection-Blöcke auf 10.000
Datensatzzeilen und Dokumente auf 200 Seiten begrenzt. Die PDF-Ausgabe
reproduziert kein CSS-Layout, keine Bilder, Farben, Typografie, SVG-Diagramme
oder präzise Tabellengeometrie. Für grafisch originalgetreue Ausdrucke bleibt
die Browser-Druckansicht zuständig. Der Versand erfolgt über den bestehenden
explizit gestarteten Outbox-Worker; automatische Hintergrundzustellung wird
nicht gestartet.
