# Zelyra 1.2.31 — tenant-aware business number series

Zelyra 1.2.31 adds declared number series to string fields used by generated
CRUD forms. For example, `customer_number: String(32) required
auto_sequence("KD-{0001}")` generates values such as `KD-0001`, while
`quote_number: String(40) required auto_sequence("AG-{year}-{0001}")` adds
the UTC calendar year and starts a separate counter each year.

The schema plan creates the managed `_zelyra_number_sequences` table. Review
and apply that migration before creating records that use a declared series.
Allocation shares the record-write transaction. Server code ignores
client-submitted values, excludes generated values from edit forms, checks
existing records, and scopes counters by resource and verified tenant. If a
series contains `{year}`, its counter also scopes by UTC calendar year.

Numbering is monotonic within the active counter but is **not gapless**.
Rollback behavior depends on the database transaction. Cancelled or voided
business documents must retain their number and audit history; Zelyra does not
reuse such values by design. MariaDB and PostgreSQL are supported for runtime
allocation. SQLite reports a clear unsupported-backend error.

MariaDB schema inspection now identifies primary-key columns from actual
`PRIMARY KEY` constraints. This avoids treating MariaDB's `COLUMN_KEY=PRI`
summary for composite unique columns as a real primary key. Applying the
managed sequence schema and planning again produces no schema drift on both
MariaDB and PostgreSQL.

This release does not add computed table fields or schema-declared CRUD file
attachments. Those remain separate planned milestones. Existing automatic
`invoice_number` behavior remains compatible when a project does not declare
`auto_sequence`.

## Limitations

The counter table is managed by Zelyra and must be included in database
backups. Schema rollout is explicit; runtime allocation does not create or
alter tables. Number formats currently support literal text, one
zero-padded counter token and optional `{year}`. A year is evaluated in UTC.
There is no browser-side number preview, and SQLite runtime allocation is not
implemented.
