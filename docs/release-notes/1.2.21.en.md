# Zelyra 1.2.21

Zelyra 1.2.21 adds checked table invariants and record-aware CRUD lifecycle
policies for business applications.

## Table invariants

Tables can declare typed cross-field `validate` rules. Declarative forms and
generated CRUD evaluate these rules before their write action and return the
declared validation message when a rule fails. APIs can opt in by binding
POST/PUT/PATCH request fields to an **unscoped** table; validation returns the
declared HTTP 422 contract before the handler runs.

Scoped API bindings remain rejected until the request runtime can provide a
verified tenant context. Raw SQL and writes from unbound handlers do not pass
through these table-invariant checks. This release does not claim that all
database writes are automatically validated.

Relation values are resolved using the schema's table naming convention and
converted to their database identity type for rule evaluation. Tables without
declared rules skip the evaluator, so unrelated custom actions do not need to
submit every column.

## Lifecycle guards and row-conditioned policies

CRUD declarations can restrict edit and delete with typed row predicates and
can attach a declared error to a lifecycle guard. The conditions are checked
against the stored record. Edit POST checks run again after acquiring the row
lock inside the write transaction; delete checks run under the mutation
transaction. A denied direct request cannot bypass the UI policy.

Detail pages and TableView edit/delete action slots can use the same policy
evaluator. A policy-aware TableView slot must identify its CRUD model and
select the complete typed row. Legacy unclassified HTML actions remain
backward-compatible and are not implicitly granted policy behavior.
