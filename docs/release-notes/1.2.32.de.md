# Zelyra 1.2.32 — berechnete Geschäftsfelder und sichere CRUD-Anhänge

Zelyra 1.2.32 ergänzt compilergeprüfte Berechnungsfelder und bindet den
privaten FileRef-Speicher an generierte CRUD-Formulare an. Zusammen mit den in
1.2.31 veröffentlichten Nummernkreisen deckt dies die fünf gemeldeten
Geschäfts-CRUD-Befunde ab.

## Berechnete Geschäftsfelder

Tabellenspalten können einen geprüften Ausdruck deklarieren:

```zelyra
table invoice_items {
    quantity: Decimal(10, 2) required
    unit_price: Decimal(12, 2) required
    total: Decimal(12, 2) required compute(quantity * unit_price)
}
```

Der Compiler prüft Feldabhängigkeiten, Ergebnistypen, Zyklen und unzulässige
Ausdrücke. Generierte CRUD-Formulare und unterstützte validierte API-
POST/PUT/PATCH-Mutationen berechnen das Feld serverseitig neu. Übermittelte
Werte eines berechneten Felds werden nicht als Eingabe übernommen. Bei
partiellen API-Updates werden ausgelassene Eingabefelder aus dem vorhandenen,
mandantengeprüften Datensatz ergänzt, bevor Validierung und Berechnung
ausgeführt werden.

Decimal-Ergebnisse werden auf die deklarierte Skala gerundet; halbe Werte
werden von Null weg gerundet. Überläufe werden zurückgewiesen. Eine
Browservorschau wird nicht als maßgebliche Berechnung verwendet.

## FileRef-Anhänge in generiertem CRUD

Eine `FileRef`-Spalte erhält Uploadgrenzen über `attachment`:

```zelyra
table contracts {
    id: Id primary auto
    title: String(200) required
    signed_pdf: FileRef? attachment {
        max_size: "20MB"
        allowed_types: ["application/pdf"]
    }
}

crud Contract -> contracts {}
```

Generierte Anlegen- und Bearbeiten-Seiten verwenden ein natives Datei-Feld.
Wird beim Bearbeiten keine Datei eingereicht, bleibt die bisherige Referenz
erhalten. Ersetzungen nutzen den bestehenden privaten, integritätsgeprüften
Speicher und werden über die vorhandene CRUD-Aktion veröffentlicht. Listen und
Details zeigen geschützte Downloadlinks statt roher Referenzwerte. Jeder
Download prüft erneut Rechte, Datensatz und Mandant. Rollback entfernt nur
gestagte Bytes.

Der `attachment`-Block verwendet die bestehende Größenrichtlinie und eine
Allowlist für PDF, PNG und JPEG. Die bestehende Request-Gesamtgrenze gilt
weiterhin. Speicheranlage ist derzeit nur unter Unix verfügbar.

## Mandanten und Lokalisierung

Übersetzungstoken in generierten Master-Detail-Legenden werden nach dem
HTML-Escaping aufgelöst. Tests prüfen eingebaute Fallbacks, Projektübersetzungen
und das Fehlen interner Tokens in der HTML-Ausgabe.

Die Nummernkreis-Funktionen aus 1.2.31 bleiben verfügbar. Nummern sind je
Nummernkreis und verifiziertem Mandanten getrennt, aber nicht lückenlos.

## Laravel-Importer

Der Importer kann eine eng begrenzte, statisch erkannte boolesche
Kontofreigabe-Sperre in `login_enabled` einer nativen Zelyra-Auth-Deklaration
übernehmen. Er kopiert keine Laravel-Konten, Passwort-Hashes oder Geheimnisse.
Administrator-Ausnahmen, Registrierung, Tenant-Auswahl, MFA und
controller-spezifische Meldungen bleiben manuelle Migrationspunkte.

## Verifikation

- Workspace-Tests, Clippy, Format- und Release-Metadatenprüfung.
- MariaDB-/PostgreSQL-Tests für berechnete CRUD- und API-Mutationen,
  partielle Updates, Mandantentrennung und Nummernkreise.
- MariaDB-HTTP- und Chromium-Tests für Upload, Erhalt und Ersetzung,
  Rollback-Bereinigung, FileRef-Ausblendung und verweigerten
  mandantenfremden Download.
- Laravel-Auth-Importer-E2E mit einer minimalen Fixture und Wegwerf-MariaDB;
  `/opt/siedelmann-laravel/app` wurde nur inventarisiert und nicht verändert.

## Grenzen

Berechnungsausdrücke sind auf die dokumentierte reine Teilmenge beschränkt.
Die statische Berechnungsvorschau ist nicht interaktiv. Die Laufzeit- und
Bytecode-Parität wird separat bis 1.3.0 geprüft. Dateispeicher und Datenbank
benötigen weiterhin getrennte Backups gemäß Handbuch; ein gemeinsames
absturzatomisches Backup wird nicht bereitgestellt.
