# Zelyra 1.4.0 — Production Core & Developer Joy

## Erstklassiger Test-Runner (`zelyra test`) & deklarative `test`-Blöcke

Zelyra bringt ab `1.4.0` eine native Testsprache und den CLI-Runner `zelyra test` direkt im Compiler mit:

```zyl
fn divide(a: Int, b: Int) -> Result<Int, String> {
    if b == 0 {
        return Err("division by zero")
    }
    return Ok(a / b)
}

test "berechnet Quotienten und meldet Division durch Null" {
    quotient = assert_ok(divide(20, 4))
    assert_eq(quotient, 5)
    assert_ne(quotient, 0)
    message = assert_err(divide(20, 0))
    assert_eq(message, "division by zero")
}
```

- **Eigenständige Testdateien:** Dateien mit `test "..."`-Blöcken benötigen kein `fn main()`. `zelyra test [pfad]` entdeckt automatisch `tests/*.zyl`, `tests.zyl` oder `main.zyl`.
- **Volle Compiler-Disziplin:** Testblöcke durchlaufen dieselbe statische Typ-, SQL-, Formular-, API- und Capability-Prüfung wie produktiver Code. Ein Test ohne `uses FileSystem` oder `uses Database` kann diese Effekte nicht heimlich nutzen.
- **Automatische Datenbank-Rollback-Sandbox:** Tests mit `uses Database` laufen gegen konfigurierte MariaDB-/MySQL- oder PostgreSQL-Datenbanken automatisch in `with_rollback_transaction` — jede Schreiboperation wird nach dem Test zuverlässig zurückgerollt.
- **CI- & KI-taugliche Ausgabe:** `--filter <teilstring>` filtert gezielt einzelne Tests; `--format json` liefert deterministisches JSON (`schema_version: "1"`) mit Laufzeiten, Ausgabe, Status und exakten Quellpositionen.

## Ausdrucksstarke Assertions über AST, MIR & Bytecode v30

Vier neue Standard-Assertions laufen mit voller Parität über Typechecker, AST, HIR/MIR und Bytecode v30:

- `assert_eq(links, rechts[, meldung]) -> Unit`
- `assert_ne(links, rechts[, meldung]) -> Unit`
- `assert_ok(result[, meldung]) -> T` (gibt den entpackten `Ok`-Wert zurück)
- `assert_err(result[, meldung]) -> E` (gibt den entpackten `Err`-Wert zurück)

## Erweiterter Zelyra Language Server (`zelyra lsp`)

- **`textDocument/formatting`:** Formatiert Zelyra-Dateien direkt im Editor über den deterministischen Zelyra-Formatter (`documentFormattingProvider: true`). Bei Syntaxfehlern bleiben Editorpuffer unverändert (leere Edit-Liste).
- **Angereichertes `textDocument/hover`:** Zeigt bei Tabellen deklarierte `states`-Übergänge inkl. `[guarded]`-Markierung und bei Funktionen `uses`-Capabilities sowie `requires`/`ensures`-Verträge an.
- **Outline & Completion:** `test "..."`-Blöcke erscheinen in `textDocument/documentSymbol`; `textDocument/completion` schlägt `assert_eq`, `assert_ne`, `assert_ok`, `assert_err`, `test`, `states` und `when` vor.

## Ehrliche Einordnung

- Native gepoolte MariaDB-/MySQL- und PostgreSQL-Treiber, String-Interpolation (`"Total: {total}"`) sowie generische Funktionen (`fn identity<T>(value: T) -> T`) waren bereits Bestandteil des Kerns und sind nun nahtlos mit `zelyra test` und dem Rollback-Sandbox-Pfad verzahnt.
- Weitergehende Punkte wie automatisches Contract-/Property-Fuzzing und der vollständige Mini-ERP Benchmark 01 bleiben als laufende Härtungsziele offen und werden nicht als abgeschlossen beansprucht.
- AST bleibt der Standard-Ausführungspfad; MIR und Bytecode v30 bleiben opt-in.
