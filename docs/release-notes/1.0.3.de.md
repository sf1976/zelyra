# Zelyra 1.0.3

Zelyra 1.0.3 bündelt die Erweiterung der eingebauten Standardfunktionen, den typisierten Pipeline-Operator `|>`, flache `else if`-Kaskaden und Verbesserungen für Studio und das Rechnungstutorial.

## 1. Erweiterte Standardbibliothek

Die neuen zustandslosen Funktionen können direkt aufgerufen werden. Pipeline-Stufen werden typgeprüft; der Zugriff auf externe Ressourcen erfordert weiterhin die passende Capability:

1. **Mathematik & Numerik:** `abs`, `min`, `max`, `clamp`, `sqrt`, `pow`, `floor`, `ceil`, `round`
2. **Strings & Textverarbeitung:** `len(String)`, `text_to_lower`, `text_to_upper`, `text_starts_with`, `text_ends_with`, `text_replace`, `text_split` (Alias: `split`), `text_pad_left`, `text_pad_right`, `text_index_of`, `text_repeat`, `text_is_empty`, `text_is_blank`, `text_capitalize`, `text_substring`, `text_trim_start`, `text_trim_end`
3. **Arrays & Sammlungen:** `sort`, `sort_desc`, `reverse`, `slice`, `concat`, `join`, `unique` (Alias: `dedup`), `array_sum`, `avg`, `min_of`, `max_of`, `chunk`, `flatten`, `zip`
4. **Mengen (Sets):** `set_union`, `set_intersection`, `set_difference`
5. **Maps & Iteration:** `get_or` (`get_or_default`), `has_key`, `map_remove`, `map_merge`, `map_increment`, `entries` (liefert Schlüssel-Wert-Tupel `(K, V)`, die `for`-Schleifen typgeprüft zerlegen können)
6. **Datums- & Kalenderarithmetik:** `date_add_days`, `date_diff_days`, `is_before`, `is_after`
7. **Ablauf- & Fehlerkontrolle:** `is_ok`, `is_err`, `is_some`, `is_none`, `unwrap_or`, `panic`
8. **Typkonvertierung & Parsing:** `to_string`, `parse_int`, `parse_float`, `to_int`, `to_float`, `parse_bool`
9. **Sicherheit & Web-Encodings:** `hash_sha256`, `base64_encode`, `base64_decode`, `url_encode`, `url_decode`, `uuid_v4` (`uses Random`)
10. **Pfade & Dateisystem:** `path_join`, `path_filename`, `path_extension`, `path_dir` (reine Pfadoperationen ohne Capability); `file_exists`, `dir_exists`, `file_size` (`uses FileSystem`)

Mathematische Funktionen prüfen Überläufe und Definitionsbereiche. `round` rundet Halbwerte weg von null und akzeptiert Nachkommastellen von `-15` bis `15`. Textlängen, Padding und Suchpositionen zählen Unicode-Codepoints; erzeugte Padding- und Wiederholungstexte sind auf 16 MiB begrenzt.

## 2. Forward-Pipeline-Operator `|>`

Zelyra unterstützt jetzt den Pipeline-Operator `|>`. Ausdrücke fließen von links nach rechts durch Transformationsketten, ohne tief verschachtelte Funktionsklammern:

~~~zelyra
bereinigt = "  kunde@beispiel.de  "
    |> text_trim()
    |> text_to_lower()
~~~

## 3. Flache `else if`-Kaskaden

Verzweigungen unterstützen jetzt direkte `else if`-Verkettungen ohne erzwungene tiefe Blockschachtelungen:

~~~zelyra
if status == 1 {
    return "Aktiv"
} else if status == 2 {
    return "Pausiert"
} else {
    return "Inaktiv"
}
~~~

## 4. Zelyra Studio & Datenbank-Robustheit

- **Deklarierte Schema-Anzeige bei Offline-Datenbank:** Ist der MariaDB-Dienst noch nicht gestartet oder die Datenbank noch nicht erzeugt, bricht Studio nicht mehr mit einem 502-Fehler ab. Alle im Quellcode (`main.zyl` und importierte Module) deklarierten Tabellen werden vollständig als *„Im Quellcode deklariert · in Live-DB fehlend“* gelistet.
- **Automatische Schema-Initialisierung:** Beim Anlegen der Datenbank in Studio wird der lokale Docker-Compose-Dienst bei Bedarf gestartet und das Schema sofort eingerichtet.
- **Freie lokale Ports:** Neue Projekte wählen freie Ports für Webserver und MariaDB. Meldet Compose beim Start dennoch einen Konflikt, versucht Zelyra begrenzt weitere Ports, aktualisiert die verwaltete `.env` samt lokaler Datenbankadresse und gibt nach dem Start die tatsächlich erreichbare Anwendungsadresse aus. Explizite Prozessvariablen bleiben maßgeblich.
- **Invoice-Beispieldaten:** Das Rechnungstutorial lädt zwei Kunden, drei Artikel, einen Rechnungsentwurf und zwei Rechnungspositionen. CLI-Setup und Studio Run laden den markierten Seed wiederholbar, ohne Datensätze zu duplizieren.
- **Begrenzte Rekursion:** Mehr als 20 gleichzeitig verschachtelte Funktionsaufrufe liefern einen kontrollierten Laufzeitfehler, bevor ein kleiner Thread-Stack überlaufen kann.

## 5. Formatter, Robustheit und Prüfung

- Der Zelyra-Code-Formatter (`zelyra fmt`) formatiert Pipeline-Operatoren `|>` und `else if`-Blöcke einheitlich und idempotent.
- Die Invoice-Anwendung wurde separat über CLI und Studio Run gestartet. Beide Vorschauen lieferten HTTP 200 mit den Beispieldaten; der wiederholte Seed legte keine Duplikate an.
- Gezielte Runtime-Tests prüfen Math-Überläufe und Definitionsbereiche, Konvertierungsgrenzen, Unicode-Indizes und sicheres Text-Padding. Die vollständigen Release-Prüfungen müssen am endgültigen 1.0.3-Commit erneut ausgeführt werden.
