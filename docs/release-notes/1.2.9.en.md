# Zelyra 1.2.9

Zelyra 1.2.9 makes declared project schedules durable through the existing
MariaDB outbox. Scheduled commands now survive service restarts and can be
inspected with `zelyra schedule jobs main.zyl`.

Only an installed, active Linux systemd service for the project enqueues work.
Manually starting `serve` does not activate schedules, and Zelyra does not
install or edit host cron entries. Jobs are project-scoped, deduplicated by
project, schedule, and UTC minute, and processed by one serial worker. The
worker rechecks current project declarations before starting a handler, uses
renewable leases and bounded retries, and never executes stored handler source.

If a schedule is removed, setup or the next active service startup cancels its
pending unleased occurrences. A currently leased occurrence is revalidated by
the worker before dispatch. `zelyra schedule jobs` returns bounded metadata
without event payloads. `zelyra outbox requeue` remains the explicit operator
action for exhausted jobs and does not send mail or execute the job immediately.

Delivery is at least once. A process crash after an external side effect but
before acknowledgement can cause a retry, so handlers should be idempotent or
use an application transaction. Schedule minutes missed while the service is
offline are not backfilled. Durable scheduling currently requires MariaDB and
the installed Linux systemd project service.
