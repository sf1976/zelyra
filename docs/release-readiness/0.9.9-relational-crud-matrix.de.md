# 0.9.9: Datenbankmatrix, Transaktionen und relationales CRUD

Datum: 13.10.2026. Unveröffentlichtes Entwicklungspaket. [English](0.9.9-relational-crud-matrix.en.md)

Dieses Paket schließt das technische Release-Gate **Abschnitt 4.A**
(Datenbankmatrix, Transaktionen und relationales CRUD) für Zelyra 0.9.9 ab.
Es belegt die exakten Datenbankversionen MariaDB 11.4.13, MySQL 8.4.11 und
PostgreSQL 16.15 in isolierten Wegwerfcontainern ohne Eingriff in bestehende
Dienste. Neben echten Fremdschlüsseln, Migrations-Preflights und restriktiver
Löschung wurden harte Schreibabbruchgrenzen (`innodb_lock_wait_timeout`) auf
MySQL gehärtet und verifiziert.

## Technische Details

1. **MySQL Lock-Wait-Härtung:** In `database/src/lib.rs` setzt `mysql_timeout_statement`
   und `mysql_session_timeout_statement` neben `max_execution_time` nun zusätzlich
   `innodb_lock_wait_timeout = lock_wait_seconds`. Dadurch greift bei Schreibsperren
   und DML-Statements das konfigurierte Zeitbudget anstelle des MySQL-Defaults von 50 Sekunden.
2. **Preflight-Prüfung `E-DB-005`:** Erkennt Fremdschlüsselverletzungen in Bestandsdaten
   vor DDL-Ausführung, meldet die verletzenden Fremdschlüssel und Tabellen und bricht ab,
   ohne bestehende Daten zu verändern.
3. **Restriktive Fremdschlüssel:** Das relationale Schema erzwingt standardmäßig
   RESTRICT; referenzierte Elterndatensätze können nicht gelöscht werden, solange
   Kinddatensätze existieren.
4. **Relationales Dropdown-Rendering:** `load_relation_options` schränkt die Optionsauswahl
   bereits auf Datenbankebene anhand der aktiven Mandanten-ID ein.

## Grenzen und offene Punkte

Das Gate 4.A belegt den relationalen CRUD- und Transaktionskreislauf auf MariaDB, MySQL
und PostgreSQL. Es belegt keine vollständige PostgreSQL-Auth-/MFA-Parität und keine
universelle Portabilität beliebiger Dialekte. Chained Audit bleibt auf MariaDB/MySQL
beschränkt.
