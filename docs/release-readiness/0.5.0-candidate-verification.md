## Downloaded artifact verification (2026-10-10)

The Actions archives from release validation run #219 were downloaded and
verified locally. `verify_release_artifacts.py --run-binary` confirmed the
Linux binary reports `zelyra 0.5.0`, and both platform archives passed checksum
and safe-path checks. `verify_sbom.py` accepted both SPDX 2.3 SBOMs with 175
packages each. The validated file hashes were:

- Linux binary: `2717b7fa539305aad7b4bac025ff9c1646cc442fd7d739ecc3946adf75b66bc1`

- Linux SBOM: `28b53c1f840dd843ed2afb72e13e340ab32b0cbb632dadcedc0cde938cf09c80`
- Windows executable: `445357d076ca32c8867685685e0d8bf7b3c7419b1de769024d815ff4c15e926b`
- Windows archive: `7efe0a315c670306a33c5cb47120862acb6be56d659e2ac874bb2d01759d8c3a`
- Windows SBOM: `f608d09e249f15e17b021668926419f019085ee0caa4440cff0c191844171ad7`

These are PR validation artifacts, not immutable public RC assets. Repeat
package verification and record public checksums against the exact candidate
tag before the human study. The Windows executable was built and verified on a
Windows runner; it was not executed on Linux.

On commit `c6d02756a8c68f919027a212db73092b3c45580c`,
`cargo test --workspace --locked`,
`cargo clippy --workspace --all-targets --locked -- -D warnings`,
`cargo fmt --all -- --check`, and
`python3 scripts/test_release_readiness.py` passed locally. The generated
project Docker E2E also passed using the local CLI/template and public compiler
commit `c5b4a262fb96e906e6c2da3086f26eb7182146a1`; this exercised the new
`git fetch` plus detached-checkout path for a commit pin. This is fixture-level
local evidence, not branch CI, candidate artifact validation, or human
acceptance. Run the independent human acceptance against the exact published RC
before the stable release.

A pull-request run validates release packages and their SBOMs but does not publish
release assets or attestations. Re-run the release workflow on the immutable RC
tag, record its public asset names and SHA-256 values, and use those exact assets
for the human study.

The Docker bundle is experimental. It must report
`source_closure_complete: false` and `complete_deployment: false`; separate
schemas/accounts and operator review are required. Complete dependency/effect
closure, shared schema ownership, and a multi-connection database module are
outside the 0.5.0 release scope.
