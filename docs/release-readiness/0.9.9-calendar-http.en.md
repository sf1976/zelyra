# 0.9.9: calendar arithmetic and temporal HTTP boundaries

Unreleased package on `fix/0.9.9-datetime-boundaries`, based on `a0cab90`.
Website files and parallel human-review results were unchanged. This neither
completes the entire date path nor 0.9.9.

## Artifact and reproduction

Linux debug compiler SHA-256: `5b923b0b37e7a8cd5aa3b976fb86dd1b8ad8d60425df6c9a4d07f629d13ac797`.
Regressions were written/run before correction: temporal forms accepted invalid
dates, API conversion produced String instead of Date, and Timestamp decoding
accepted values outside ISO bounds. The real HTTP probe failed with
`invalid operation GreaterEqual for String and Date`. The generated-client
probe found Timestamp described as String despite existing integer output.

## Corrections

- Shared Gregorian/UTC validation in `ast/src/temporal.rs`; existing correct
  arithmetic is retained and independently compared. No Float intermediates
  or local time-zone discovery.
- Date/Time forms reject invalid calendar/clock values; table-bound temporal
  aliases use the same rules.
- HTTP data becomes actual Date/Time/Timestamp/Duration runtime values,
  including records and optional fields. Invalid data produces HTTP 400.
- Timestamp input and `format_timestamp` are bounded to ISO years 0001–9999.
  Runtime input errors have source positions. HTTP/form timestamps also accept
  exactly representable UTC ISO text with Z besides milliseconds.
- OpenAPI/TypeScript correctly describe existing output wire formats; language
  JSON output is not changed. Bilingual validation, rules, specification,
  type inventory, and a runnable example are included.

## Limits and next work

Date/time storage, PostgreSQL codecs, Timestamp precision, and fully typed
SQL result consumption remain separate technical gates. Existing raw SQL row
representation is not changed here. Time zones, DST, and leap seconds are
explicitly excluded. The full date path is verified only after real database
round trips. The next package must close these gaps before the 0.9.9 freeze;
IDE expansion remains scheduled after technical defects.
