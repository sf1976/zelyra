# 0.9.9 SQL result materialization package

Date: 2026-10-13. Snapshot: unreleased development package; 0.9.9 is unfinished.
[Deutsch](0.9.9-typed-sql-results.de.md)

## Outcome and acceptance

`sql_decode<T>(sql<…> { … })` explicitly materializes scalar, flat record,
array and optional results. Cardinality, column projection/order, native type
families, cell ranges/precision and NULL values are checked with source spans.
Existing SQL/schema/parameter/capability checks remain. Raw SQL and raw-row
HTTP/JSON output retain their existing string values and `\N` sentinel.

- MariaDB/MySQL and PostgreSQL retain native NULL flags independently from
  text; a real NULL and the literal `\N` decode to distinct values.
- Exact Decimal, DECIMAL(19,4) Money, UInt and Int conversion never uses Float.
  Native Float columns cannot supply an exact numeric target. Finite Float
  conversion remains an explicit approximate target.
- Native Date/Time/UTC Timestamp results support real calendar/UTC arithmetic,
  including MySQL/MariaDB date-only midnight text and exact .001/.999 values.
- Aliases, concrete generic records and synthesized table rows work, including
  nullable stored columns and stored relation IDs. Missing/extra/duplicate
  columns and unsupported shapes fail even with no rows.
- Invalid decoder syntax/shapes use `E-TYPE-SQL-DECODE`; conversion errors use
  the existing source-located runtime diagnostic with column and row context,
  without echoing cell contents. Direct SELECT expressions preserve explicit
  database effects; this introduces no dynamic SQL-string API.

The bounded acceptance target and compatibility decision are documented in
[the language rules](../sql-results.en.md). The executable example is
[typed_sql_results.zyl](../../examples/typed_sql_results.zyl).

## Limits and release state

Builtin Money JSON now restores its exact Decimal value instead of text; Id
JSON adds integer input while retaining legacy string input. Explicit aliases
still override these builtin representations. The native regression probe
checks a complete Date/Time/Timestamp/Decimal/UInt/Money/NULL DTO round trip.
The generated-business rehearsal also passes on the final artifact, including
bounded, redacted storage-preflight refusal before startup.

This is an explicit compatibility-preserving API; legacy raw annotations are
still metadata, not materialized values. Applications choose decoding and must
version an existing HTTP endpoint if its wire shape changes. Flat scalar fields
are supported; nested records/collections, enums, Bytes, classes and unresolved
generic targets are rejected. Text domains gain no new content validation or
identity semantics. Explicit aliases/records retain precedence. Binary MySQL/
MariaDB strings are rejected as text. Results are eagerly held in memory; SQL
LIMIT/pagination remains the application's responsibility.

There is no added dependency, provider, telemetry, service, environment switch,
or database migration. Local control, native replaceable backends, explicit
capabilities and migration approval remain. Existing years/timezone/precision
limits apply. This establishes neither complete PostgreSQL CRUD/auth parity
nor a production release, resource benchmark, immutable release artifact or
human acceptance. Subsequent security/backend/migration/packaging gates remain;
IDE work comes afterward. The website was not edited. GitHub CI on the pushed
package is a separate integration gate, not a local-test claim.
