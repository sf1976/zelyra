# Zelyra 1.3.0 — Release candidate verification

Status: v1.3.0 published; installation and update paths verified.

## Implemented scope

- The opt-in standard layout includes compiler-checked MariaDB minimal, CRUD,
  auth, and business starters.
- `strict_architecture` checks statically resolved route/API/form calls, write
  SQL or SQL that cannot be safely classified, and forbidden imports from
  `routes/` into `domain/`. Unresolved dynamic flows are not treated as
  verified.
- `migrate-layout --check` reports deterministic, source-mapped findings per
  declaration and does not change files.
- Studio provides compiler-aware import, signature, record-field, SQL-column,
  CRUD/form scaffold, and known inferred local type suggestions. Source is
  changed only after selection.
- AST remains the default. MIR and Bytecode are experimental opt-in backends
  that reject unsupported execution paths.

## Open limits

This release does not include a completed Mini-ERP. The standard business
starter verifies selected CRUD/API flows, not complete purchasing, sales,
inventory, invoicing, authorization, or concurrency workflows. The Mini-ERP
and the preceding password-generator application belong to the following
1.3.x hardening effort. Bytecode parity and any default-backend change are not
part of this release.

Publication and installation are complete. The Mini-ERP is outside the scope
of 1.3.0 and remains part of the following 1.3.x hardening work.
