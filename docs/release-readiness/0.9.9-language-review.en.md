# Zelyra 0.9.9 language review

**Review date:** 2026-10-12 · **Compiler:** source-built `zelyra 0.9.9` ·
**Platform:** Linux x86_64, glibc 2.41
**SHA-256:** `89b880d753e12ac09b2fbb4dc754586d18c7a808845b991b331cb1ae00153c0d`
**Source revision:** `1bf09ea` · rerun after the Rust compatibility fix

This reruns the supplied 0.9.7 review cases against the 0.9.9 development
branch. The `gap-*` probes now use the accepted 0.9.9 syntax for features that
were missing in the original baseline. This is a source-build language and CLI
result; it does not certify a release archive or database, HTTP, SMTP, Windows,
security, or production behavior.

## Results

- 80 cases: 76 met their expected behavior and 4 were explicitly classified as
  observations; there were no unexpected outcomes.
- All 20 task programs passed.
- All 35 expected compile-time and runtime negative cases failed in a controlled
  way: 14 compile diagnostics and 21 runtime rejections.
- 100/100 repeated task runs passed.
- 400 independent numeric comparisons passed: 300 integer division/remainder
  comparisons and 100 Decimal additions. The fixed seed and Python reference
  run are reproducible with `scripts/check_numeric_references.py`.
- The added class regressions pass: shared identity, field mutation, generic
  classes, optional fields, incorrect field types, value Records, JSON/API
  boundaries, cycles, and parallel mutation. These run alongside the 80-case
  probe in `cargo test --workspace` and the type-system integration test.
- Deep recursion is rejected with a controlled source-located runtime error
  instead of a process abort. Missing and partial non-Unit return paths are
  compile-time errors. The direct `Int::MIN` literal is accepted.

The four observations are bounded behavior, not unexpected failures:

1. The normal CLI has no implicit step deadline; the separate loop probe is
   stopped by the harness. Use `zelyra run --max-steps <n>` for bounded runs.
2. Decimal arithmetic has a fixed nine-digit scale and multiplication/division
   truncate excess digits. `decimal_quantize_result` supplies explicit rounding.
3. A 5,000-term left-associated expression evaluates successfully.
4. Deep recursion now produces a runtime diagnostic rather than a crash; the
   language does not promise tail-call optimization or unlimited stack use.

## Language scope recorded for 0.9.9

Implemented additions include generic functions, generic Records and Enums,
payload-carrying variants with exhaustive matching, typed values for named
non-generic functions, exclusive integer range loops, typed value updates for
Records and arrays, date arithmetic, timestamp ordering, tagged Result JSON,
Decimal quantization, direct `Int::MIN` literals, complete non-Unit return
analysis, and explicit scalar `format_text` conversion. Classes add shared
reference identity, typed field mutation, generic type parameters, and optional
fields. They have no method or inheritance syntax; behavior uses ordinary
functions with an explicit receiver parameter. Class references and Records
that contain them cannot be serialized directly through JSON, HTTP, or SQL.

Closures, generic function references, generic aliases, and general
trait/constraint bounds remain explicitly outside the tested scope. The type
inventory continues to document partial function-value support.

## Reproduction

From the repository root:

```bash
python3 /opt/siedelmann-laravel/zelyra-sprachpruefung/pruefen.py \
  --compiler target/debug/zelyra --allow-other-compiler
python3 /opt/siedelmann-laravel/zelyra-sprachpruefung/wiederholen.py \
  --compiler target/debug/zelyra --allow-other-compiler
python3 scripts/check_numeric_references.py --compiler target/debug/zelyra
```

The first command reports all 80 cases; the second runs the 20 tasks five
times each and repeats the critical failure probes. The third compares 300
integer division/remainder pairs and 100 Decimal additions with independently
calculated Python results. The corpus is a local language regression set, not a
general production-readiness assessment.
