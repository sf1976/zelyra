## Beobachtungen und Fehler

Die beiden gemeldeten Fehler sind in 1.0.1 behoben: Python Compose v1 wird vor
dem `ContainerConfig`-Absturz abgewiesen, und Studio verwendet beim Starten den
vorhandenen Dateibaum statt der undefinierten Variablen `files`. Docker Compose
v2 oder neuer bleibt Voraussetzung. Der Ubuntu-Crashreport-Rechtefehler wird
nicht mehr als fehlender Docker-Socket-Zugriff eingeordnet.

In den zusätzlichen Prüfungen wurden keine weiteren unerwarteten Fehler
gefunden. Die vier bekannten Beobachtungen bleiben begrenzt: tiefe Rekursion
endet mit einer kontrollierten Diagnose; eine unbeschränkte Endlosschleife
wird extern beendet (für begrenzte Ausführung `--max-steps` nutzen); Decimal
verwendet neun Nachkommastellen und schneidet nicht darstellbare Stellen ab;
eine linksassoziierte Ausdruckskette mit 5.000 Summanden läuft erfolgreich.
Diese Linux-Prüfung ist kein vollständiger Sprachtest auf Windows und kein
Nachweis universeller Fehlerfreiheit.

## Reproduktion

Das externe 80-Fälle-Paket wurde in eine eigene temporäre Kopie übernommen;
das bestehende Prüfungspaket wurde nicht überschrieben.

```bash
python3 /tmp/zelyra-101-language/pruefen.py --compiler <verifiziertes-binary> --allow-other-compiler
python3 /tmp/zelyra-101-language/wiederholen.py --compiler <verifiziertes-binary> --allow-other-compiler
python3 scripts/check_numeric_references.py --compiler <verifiziertes-binary>
python3 scripts/check_calendar_references.py --compiler <verifiziertes-binary>
```

Für die HTTP-/SQL-Prüfungen `ZELYRA_BIN` auf das verifizierte Binary setzen und
`DATABASE_URL` ausdrücklich auf eine eigene Testdatenbank richten. Ausführen:
`tests/exact-numbers-e2e.py`, `tests/temporal-sql-e2e.py` für beide Backends und
`tests/temporal-api-e2e.py`. Die vollständigen Ergebnisse enthalten den Hash.
