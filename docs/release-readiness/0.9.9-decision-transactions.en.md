# 0.9.9: native decision transaction foundation

Date: 2026-10-13. Unreleased development package. [Deutsch](0.9.9-decision-transactions.de.md)

`with_decision_transaction` provides conditional reads and writes on one borrowed
connection for MariaDB, MySQL and PostgreSQL. Execution failures poison the
transaction even when a callback ignores them. Errors, expired deadlines and
unwind prevent commit. Transaction control and implicit-commit DDL are refused;
the existing generated MariaDB/MySQL audit initialization remains allowed.
Ordinary MariaDB closure transactions also roll back/discard on unwind and
failed commit. PostgreSQL uses driver transactions and local statement timers.

## Remaining gates

This API is groundwork. PostgreSQL guarded-form adapters, membership/recipient
races, NULL-aware edit checks and atomic audit integration remain open; no web
guard is removed. PostgreSQL chained audits, full auth/MFA/notification parity,
hard in-flight MySQL write bounds and independent security acceptance are not
proved here. No automatic retry or universally knowable commit outcome is
claimed. No dependency, environment switch, migration, provider, telemetry or
website change. See [API rules](../decision-transactions.en.md).
