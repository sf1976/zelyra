# 0.9.9: natives NULL bei optimistischen Edits

Datum: 13.10.2026. Unveröffentlichtes Entwicklungspaket. [English](0.9.9-null-edit-snapshots.en.md)

Eine echte HTTP-Regression am vorigen SQL-Artefakt zeigte: Ein mit NULL geladener
Edit konnte eine inzwischen auf Literaltext `\N` geänderte Zeile überschreiben.
Beide Werte wurden als gleicher String signiert; die veraltete Anfrage lieferte
303. Die erste Probe zeigte zudem fehlende `:note`-Parameter bei ausgelassenen,
implizit nullable Feldern (500).

Edit-Snapshots signieren nun natives NULL als JSON-null und Literaltext als
Strings. GET leert nur tatsächlich NULL enthaltende Eingaben. Der gesperrte
transaktionale Vergleich weist beide NULL-/Literal-Wechsel mit HTTP 409 vor dem
Schreiben ab. Fehlende/inkonsistente Metadaten scheitern. Nullable Speicher wird
in Formularwerttypen berücksichtigt; fehlende/leere optionale Werte binden
natives NULL. Pflicht-/Readonly-Prüfung, CSRF-/Feldmengenbindung und zeitkonstanter
HMAC-Vergleich bleiben. Snapshot-Logik liegt in `web/src/edit_snapshot.rs`.
