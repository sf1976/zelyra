# Zelyra 0.4.0 coverage-guided fuzzing record

**Date:** 2026-10-09 · **Status:** local smoke evidence; not a candidate-length
security review.

## Setup and commands

- `cargo-fuzz` 0.13.2, Rust nightly `1.101.0-nightly` (`a30aa9064`), and Clang
  19 on Linux x86_64.
- `CC=/usr/lib/llvm-19/bin/clang cargo +nightly fuzz build`
- Each target ran locally with `-max_total_time=10 -max_len=16384 -timeout=5`.
- CI is configured to run each target for 15 seconds, preserve crash artifacts,
  and pin the nightly channel to `nightly-2026-10-09`.

## Crash found and regression

The first lexer/parser run found a panic. `cargo fuzz tmin` reduced its input to
the following 9-byte case:

```text
fn e(){n*
```

The parser consumed its EOF token while reporting the missing right-hand
expression, then indexed past the token vector. The parser now keeps EOF
available while reporting errors and adds a sentinel EOF for callers that omit
one. The minimized input is checked in at
[`fuzz/corpus/lexer_parser/parser_missing_rhs`](../../fuzz/corpus/lexer_parser/parser_missing_rhs).
Parser unit tests verify both the error result and missing-EOF handling. The
post-fix fuzz run completed all four targets without a crash.
