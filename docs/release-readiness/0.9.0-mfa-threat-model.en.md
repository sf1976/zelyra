# Zelyra 0.9.0 local MFA threat model (draft)

Status: implementation review draft. This document is not an independent
security assessment and does not establish release readiness.

## Assets

- TOTP seed and its encryption key.
- Password-only pending sessions and authenticated sessions.
- Recovery-code verifiers and their single-use state.
- MFA enrollment, disable, and recovery-code replacement actions.

## Threats and current controls

| Threat | Current control in the 0.9.0 branch | Evidence still required |
| --- | --- | --- |
| Database reader obtains TOTP seed | AES-256-GCM encryption with an operator-managed 32-byte key; authenticated associated data and random nonce | Independent review of key handling, nonce use, backup/restore and memory lifetime |
| Password theft alone grants access | Persistent sessions start with `mfa_verified = false`; guarded routes require it to be true | Integration coverage across pages, APIs, CRUD, account sessions, and logout |
| OTP replay or concurrent reuse | Factor row lock and stored accepted TOTP counter in the same MariaDB transaction as session promotion | MariaDB concurrency test against supported server versions |
| Recovery code replay | Argon2id verifier, locked unused row, and `used_at` update in the same transaction as session promotion | Concurrent recovery-code test and migration/backup review |
| Online guessing | Five failed MFA attempts set a 15-minute lock on the factor row | Tests for boundary timing, lock expiry, and behavior across multiple processes |
| Cross-site settings changes | CSRF token plus same-origin validation; password and current TOTP required for disable/rotation | Browser-level CSRF and origin tests |
| Secret leakage in HTML caches or logs | Secret pages use `Cache-Control: no-store`; diagnostics omit codes and seeds | Proxy/browser cache review and log inspection |
| Key loss or operator lockout | No in-app key rotation or recovery flow exists; a database recovery runbook is documented | Rehearse the runbook and review its audit trail without exposing the seed |

## Assumptions and limits

The application host and its environment are trusted. A compromised application
process can read the encryption key and plaintext seed during verification.
The current implementation supports MariaDB-backed sessions only. TOTP
authenticator interoperability, clock skew, operational key rotation, and
recovery after a lost authenticator require review before release. The current
default accepts the current 30-second TOTP step plus one step on either side.

## Release blockers

Complete integration coverage, schema migration review, a rehearsal of the
bilingual operator recovery runbook, an independent security review, and human
review of the candidate artifacts before publishing 0.9.0.
