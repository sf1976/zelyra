# 0.9.9: native NULL in optimistic edits

Date: 2026-10-13. Unreleased development package. [Deutsch](0.9.9-null-edit-snapshots.de.md)

A real HTTP regression on the preceding SQL artifact showed that an edit loaded
with NULL could overwrite a row changed to literal `\N`: both were signed as the
same string and the stale request returned 303. The first probe also exposed
missing `:note` parameters for omitted implicitly nullable fields (500).

Edit snapshots now sign native NULL as JSON null and literal text as strings.
GET display blanks only actual NULL. The locked transactional comparison rejects
both NULL/literal transition directions with 409 before writing. Missing or
inconsistent metadata fails closed. Nullable storage is reflected in form value
types, so omitted/empty optional values bind native NULL. Required and readonly
validation, CSRF binding, field-set binding and constant-time HMAC comparison
remain. Snapshot logic is extracted into `web/src/edit_snapshot.rs`.
