# Zelyra 0.9.4 CLI and Studio readiness evidence

This release audit covers the documented command surface and reported setup
paths. It is not a claim that every possible argument permutation has been
exhaustively tested.

## Command surface reviewed

- Top-level help includes the editor, route inspection, tutorial, database
  history, and outbox commands.
- The integration matrix invokes documented nested help paths in German and
  English, checks command-specific content, and covers representative success
  and expected-error cases for form validation, database commands, setup, and
  text editing.
- Database help distinguishes `db create` (emit checked SQL) from `db setup`
  (initialize a configured MariaDB database and schema). `setup <directory>
  --all` starts the local Compose project and applies its declared schema.
- Schema setup now retries transient connection failures only. A non-retryable
  migration error is returned immediately with its details; explicitly risky
  changes still require a reviewed plan and `db apply --allow-risky`.

## Live setup and Studio evidence

- `zelyra setup <directory> --all` completed against a disposable MariaDB
  Compose project. Compose output and schema progress were visible, and the
  selected local application URL was printed.
- The tutorial schema was applied twice. `db plan --format=json` reported no
  drift after the MariaDB `DECIMAL` equivalence correction.
- The Studio-compatible customer flow loaded `/customers/new`, submitted a
  customer with its CSRF token, followed the redirect, and found that customer
  in `/customers` against the same local MariaDB-backed preview.
- The CRUD query failure text now directs users to check that the database is
  running and the project schema is applied. SQL errors and credentials remain
  server-side.
- `tests/invoice-tutorial-e2e.sh` covers tutorial CSS, protected `.env`, schema
  idempotency, and customer create/list behavior.
- After a successful automatic tutorial setup, Zelyra opens the default browser
  when a graphical session is available. Headless runs print the application
  URL; `--no-start` skips stack startup, schema application, and browser launch.
  Unit coverage checks
  the URL handoff and headless fallback without launching a real browser.
- Studio database creation now connects through the MariaDB driver instead of
  requiring a host `mariadb` executable. For generated local projects it uses
  the protected Compose root password to create a missing database, with the
  configured application account as a fallback. Credentials stay server-side.
  The MariaDB Studio E2E now starts from a missing database and uses an
  application account with database-scoped grants only.
- `db setup` is exercised against another initially missing MariaDB database,
  so both CLI schema bootstrapping and Studio database creation cover the
  create-then-use path.

## Automated checks

On the release candidate before the version bump, all of these passed:

```text
cargo fmt --all -- --check
cargo test --locked --workspace
cargo clippy --locked --workspace --all-targets -- -D warnings
python3 scripts/validate_handbook.py
```

The workspace run included the bilingual CLI help matrix, CRUD error-message
regression, MariaDB decimal-equivalence tests, and tutorial tests. Re-run the
same checks and release metadata validation on the final 0.9.4 commit.

## External update check

During local verification, GitHub's unauthenticated release API returned HTTP
403 because its rate limit was exhausted. `zelyra update --check` now gives a
specific recovery message for HTTP 403/429. This network limitation did not
affect local build, setup, Studio, or release validation.

## Acceptance boundary

Zelyra 0.9.4 remains experimental. This engineering verification does not
replace the independent human acceptance reserved for 1.0.0.
