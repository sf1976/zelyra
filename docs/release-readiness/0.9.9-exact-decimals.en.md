## Fixed defects

- Money/Decimal crossed form, filter, and HTTP boundaries through Float.
  Exact lexemes are now retained; NaN, infinity, wrong scales, and range errors
  are rejected.
- Unqualified MariaDB Decimal silently lost fractions through the server's
  `(10,0)` default. New storage is `(39,9)`; Money keeps `(19,4)`. Legacy scales
  fail before SQL or server startup without silent migration. PostgreSQL
  inspection preserves precision and scale.
- Validated empty optional form inputs subsequently failed. Actions receive
  validated values; empty optional fields bind NULL.
- Decimal aliases failed return/SQL checks and optional alias columns became
  TEXT. Underlying-type checks and exact storage are now consistent. Cyclic or
  excessive alias expansion receives controlled static diagnostics.
- Multiplication/division rejected valid results because of intermediate
  overflow. Bounded wider exact intermediates fix this while real result
  overflow still fails. Extreme negative remainder caused a Rust panic and
  now correctly returns numeric zero.
- serde's global lossless-number feature normally reinterprets particular
  reserved object keys. An explicit decoder preserves ordinary objects and
  numeric lexemes without Float conversion.
- A full development run found SIGABRT during deep recursion on the ordinary
  Rust test stack. Record construction and parallel execution are extracted
  from recursive dispatch frames. The 24-call limit remains; direct/mutual
  recursion and valid small recursion pass.
- MySQL HTTP reads attempted to set a MariaDB timeout variable. Engine
  selection now uses MySQL's variable; this does not prove equivalent write
  time limits.

## Newly supported paths

PostgreSQL NUMERIC results, type-independent NULL, and the full UInt range
bind/decode without Float. Generated identifiers remain quoted correctly;
literals, comments, and dollar strings are preserved. Plain form actions use
atomic PostgreSQL transactions. CRUD read/filter, tableview, page, and relation
paths use the backend dispatcher. OpenAPI/TypeScript correctly describe Decimal
responses as strings. A runnable 19-percent invoice example, bilingual rules,
and CLI form help are included.

## Compatibility and remaining technical work

Decimal JSON responses remain strings; generated clients are corrected to
match. Constructors stay strict; HTTP JSON numbers may contain exactly
representable exponents. Silent input-scale rounding and nonfinite inputs are
not retained. Older databases require a reviewed plan; already lost digits
cannot be reconstructed.

PostgreSQL tenant/recipient actions, edit snapshots, audit/auth decisions, and
full backend parity remain technical gates within 0.9.9. MySQL write-interruption
bounds and SQLite Decimal runtime storage are not established by this package.
There is no new cloud requirement, telemetry, AI integration, or uncontrolled
migration. `bytes` and pinned `num-bigint 0.4.8` are now direct dependencies but
already existed in the unchanged dependency-version graph; no new external
runtime service is required.

The existing raw SQL row representation remains: declared result types are
metadata, not complete evidence of typed scalar/record consumption. Cardinality,
NULL/text distinction, and typed downstream use require a separate technical
package before the freeze.
