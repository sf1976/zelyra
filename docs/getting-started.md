# Getting started with Zelyra

[Deutsch](getting-started.de.md) · English

Zelyra is designed so a beginner can get from download to a running program
with as little system setup as possible.

## 1. Install

Download or clone the repository, enter its directory, and run:

```bash
./install.sh
```

The installer is user-local. It does not require `sudo`, Apache, a database,
or a pre-existing Rust installation. If Rust is missing, it installs the
official stable toolchain for the current user through `rustup`.

The default binary location is `~/.local/bin/zelyra`. If that directory is not
on `PATH`, add it once:

```bash
export PATH="$HOME/.local/bin:$PATH"
```

For maintainers and contributors, the equivalent development command is:

```bash
cargo run -p zelyra-cli -- run examples/fibonacci.zyl
```

## 2. Run the first program

```bash
zelyra run examples/fibonacci.zyl
```

The result is:

```text
55
```

Use `zelyra check program.zyl` to type-check without executing it.

## 3. Database setup without framework configuration

For local projects, Zelyra can use SQLite without a separate server:

```bash
export DATABASE_URL='sqlite:///tmp/my-app.sqlite3'
zelyra db bootstrap examples/machine_management_sqlite.zyl
zelyra db inspect examples/machine_management_sqlite.zyl
```

MariaDB is supported directly as well. Credentials are passed only through
`DATABASE_URL` or a secret manager:

```bash
export DATABASE_URL='mariadb://user:password@127.0.0.1:3306/my_app'
zelyra db bootstrap examples/machine_management_mariadb.zyl
```

This keeps the first setup free of Apache and a separate ORM.

## 4. Web setup policy

The web platform will provide a built-in development server, so a new user
will be able to start an application without installing Apache or configuring
PHP, a separate frontend server, or a reverse proxy.

For production, Zelyra will support two equally valid paths:

1. run the standalone Zelyra server directly;
2. put Zelyra behind an existing Apache, nginx, Caddy, or cloud load balancer.

Apache configuration will be generated by Zelyra when requested. It will be an
adapter, not a mandatory part of the language runtime. TLS, process
supervision, firewall rules, and database credentials will remain explicit
deployment concerns and will not be hidden by the compiler.

The commands `zelyra dev`, `zelyra serve`, and `zelyra web apache` are planned
for the Web Core phases. Phase 1 intentionally has no web server yet.

## 5. Design requirements for future installers

Release builds should provide a platform-specific standalone binary, allowing
end users to install Zelyra without Rust. Package managers and container images
may be added later, but the first-run path should remain:

```text
download → zelyra new my-app → zelyra dev
```

No account password should be required for a user-local installation.

## 6. Documentation languages

Core documentation is maintained in both German and English. New documents
should either be bilingual or have a matching German variant with the `.de.md`
suffix. Changes to installation, the CLI, and the user experience must be
updated in both language versions.
